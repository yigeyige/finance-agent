# 简要测试方案

> 上级索引：[开发任务总览](00-财务共享智能运维Agent-开发任务总览.md)
> 原则：本方案只定义必要测试和责任，不代替[详细验收附件](../生产落地技术方案/附件D-测试验收与P0清单.md)。

## 1. 测试目标

1. 证明核心 Agent 能以合成数据完成有界只读调查、人工逐步确认、证据计算、复核发布和交接。
2. 证明业务状态机始终高于 Harness 状态，模型和工具不能越权。
3. 证明禁止字段、源写入和未复核发布三项硬门禁为零。
4. 证明 JAR/Docker、PostgreSQL 状态和中断恢复具备可重复结果。

## 2. 分层与责任

| 层次 | 内容 | 实现方 | 用户 |
|---|---|---|---|
| 编译/静态 | Maven、TypeScript、前端构建、ArchUnit、Flyway 静态检查 | 执行 | 可复验 |
| 契约 | OpenAPI、JSON Schema、工具/源/模型 Stub、摘要向量 | 执行指定部分 | 执行其余场景 |
| 数据库 | 迁移、约束、事务、租约、回滚 | 提供脚本和代码 | 在现有 PG 容器执行 |
| 纵向流程 | 合成任务从发起到交接 | 提供步骤和修复 | 启动环境并执行 |
| Harness | Session、HITL、PG 状态、压缩、Workspace、Skills、Subagents、Memory、Sandbox | 实现和静态/契约检查 | 运行能力与故障场景 |
| 模型 | HTTP Stub 和结构 schema | 执行 | 手动调用真实 DeepSeek |
| UI | 类型和构建 | 执行 | 浏览器人工验收 |
| 安全负向 | 禁止字段、越权、写源、未审发布 | 提供用例/扫描 | 执行运行态场景 |
| 部署 | 前端静态产物、后端 JAR、前端/后端镜像构建 | 执行 | 分别启动前端和后端，检查页面、API/健康端点及网关路由 |

## 3. 建议本地命令

具体脚本名称以工程初始化后的实际文件为准，任务要求至少提供等价入口：

```text
backend/mvnw -q -DskipTests package
backend/mvnw -q test -Dtest=*ContractTest
frontend/npm ci
frontend/npm run typecheck
frontend/npm run build
scripts/verify-contracts
scripts/scan-sensitive-markers
```

真实 DeepSeek 使用独立命令，例如：

```text
DEEPSEEK_API_KEY=<由用户注入> backend/mvnw -Pmodel-live-test -Dtest=*DeepSeekLiveTest test
```

Windows 最终命令由工程任务同时提供 PowerShell 版本。默认构建和测试不得访问真实 DeepSeek。

## 4. P0 最小测试集

### 4.1 正常路径

- 创建任务并记录合成人员离职前提；
- 确认范围和三类字段策略；
- Harness 提议、人工批准和合成源查询；
- 生成当前/未来/未知、coverage 和 computation witness；
- 人工确认专业判断；
- 草稿、准确复核、全范围重查、发布、VIEWER 查看和交接。

### 4.2 必须负向

- 未确认/旧/过期审批；
- 字段、范围、模板或来源漂移；
- 允许读但禁止留存字段；
- 禁止读取字段；
- 写源尝试；
- 分页缺失、来源冲突和生效时间跨越；
- 未确认专业判断、旧 review 和审计失败；
- 双 Worker、重复请求、租约过期和多个中断点；
- prompt 注入、未知工具、子 Agent 增权、技能篡改和 workspace 路径逃逸；
- reasoning_content 向日志、数据库、checkpoint 或 SSE 泄漏。

## 6. P0 结束条件

- 编译、类型、契约和制品检查通过；
- 用户完成合成纵向流程、恢复、Harness、真实 DeepSeek 和 JAR/Docker 验证；
- 禁止字段持久化或送模、源写入、未复核发布均为 0；
- 未执行项明确为未执行，不以“代码已实现”替代验证；
- P0 证据包和进入 P1 的阻断清单完成。
