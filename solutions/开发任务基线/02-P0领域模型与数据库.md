## DEV-DATA-001 建立 Flyway 基线和 schema

- **状态**：`TODO`
- **依赖**：`DEV-BOOT-007`。
- **目标**：用可重复验证的迁移建立 Agent 自有数据边界。
- **实施**：创建 `iam`、`task`、`evidence`、`packet`、`harness`、`knowledge`、`governance` schema；按附件 A 拆分版本迁移；扩展由平台/准备脚本确认，应用迁移不获取超级权限。
- **产物**：Flyway V1 基线、迁移说明、校验查询。
- **验收**：空库迁移成功；重复启动不重复建表；schema history 完整。
- **负向检查**：应用账号执行 DDL 失败；版本低于基线时拒绝继续。
- **实现方检查**：Flyway 脚本静态检查、编译。
- **人工验证**：用户在现有容器执行迁移和权限负测。
- **完成证据**：迁移记录、schema 清单、用户验证结果。

## DEV-DATA-002 建立身份和运行版本模型

- **状态**：`TODO`
- **依赖**：`DEV-DATA-001`。
- **实施**：实现 `agent_user`、`role_binding`、`runtime_bundle` 表与 Spring JDBC 仓储；P0 合成用户包含 OPERATOR、VIEWER、PLATFORM_ADMIN；运行版本冻结应用、AgentScope、模型、提示、规则、工具和源目录版本。
- **产物**：迁移、领域对象、仓储、合成种子数据（仅 local/test）。
- **验收**：唯一人员编号和 auth subject 唯一；角色撤销可追踪；任务只能引用已发布 runtime bundle。
- **负向检查**：`prod` 禁止加载合成用户；未发布 bundle 创建任务失败。
- **实现方检查**：仓储契约检查、编译。
- **人工验证**：用户查询数据库记录。
- **完成证据**：表结构、契约结果、样例记录。

## DEV-DATA-003 建立任务、范围、前提和步骤模型

- **状态**：`TODO`
- **依赖**：`DEV-DATA-001`。
- **实施**：实现 `investigation_task`、`scope_revision`、`task_premise`、`investigation_step`、`step_approval`、`task_lease`、`tool_invocation`；范围三类字段权限使用有版本 JSON Schema 的 JSONB；核心关系用外键。
- **产物**：迁移、领域对象、显式 SQL 仓储、映射器。
- **验收**：范围不可原位修改；一步一审批；一个任务最多一个活动租约；乐观版本可检测并发修改。
- **负向检查**：第二活动租约、过期审批、旧 scope revision 引用失败。
- **实现方检查**：SQL/仓储契约检查、编译。
- **人工验证**：用户执行并发/约束 SQL 用例。
- **完成证据**：约束清单、SQL 用例结果。

## DEV-DATA-004 建立证据、覆盖度和判断模型

- **状态**：`TODO`
- **依赖**：`DEV-DATA-003`。
- **实施**：实现 `fact_snapshot`、`coverage_record`、`finding`、`finding_evidence`、`computation_witness`、`professional_confirmation`；字段快照只接收已裁剪值；当前/未来/未确定使用受控枚举。
- **产物**：迁移、领域对象、仓储和规范化映射。
- **验收**：每条确定性 finding 可追到 witness 和快照；人工判断逐项绑定确认；覆盖记录能表达 COMPLETE/PARTIAL/UNKNOWN。
- **负向检查**：无证据确认、无 witness 的确定性 finding、无人工确认的专业 finding 均不能进入可发布状态。
- **实现方检查**：领域守卫和 schema 契约检查。
- **人工验证**：用户抽查数据库证据链。
- **完成证据**：样例证据链和约束结果。

## DEV-DATA-005 建立决策包、复核、发布和交接模型

- **状态**：`TODO`
- **依赖**：`DEV-DATA-003`、`DEV-DATA-004`。
- **实施**：实现 `packet_draft`、`packet_review`、`packet_revision`、`handoff`；规范 JSON 为权威内容，HTML 为快照；review 绑定准确 digest、范围和 runtime bundle；已发布修订不可变。
- **产物**：迁移、领域对象、仓储、不可变写策略。
- **验收**：同任务修订号唯一；更正只创建新修订；VIEWER 查询只返回发布版本。
- **负向检查**：更新/删除已发布 revision、摘要不符 review、未发布草稿 VIEWER 访问失败。
- **实现方检查**：仓储契约和权限 SQL 检查。
- **人工验证**：用户执行已发布记录更新负测。
- **完成证据**：不可变性结果和样例版本链。

## DEV-DATA-006 建立 Harness 状态与 checkpoint 模型

- **状态**：`TODO`
- **依赖**：`DEV-DATA-003`。
- **实施**：实现 `harness.session_state`、`harness.checkpoint`、计划修订和 workspace 引用表；业务 task/user/session 显式关联；状态内容使用 schema 版本、摘要和最小恢复引用。
- **产物**：迁移、仓储、状态序列化接口。

- **负向检查**：旧 scope/approval checkpoint 恢复校验失败。
- **实现方检查**：序列化和字段白名单契约检查。
- **人工验证**：用户抽查 checkpoint 内容。
- **完成证据**：schema、样例 checkpoint 和扫描结果。

## DEV-DATA-007 建立审计和本地 outbox

- **状态**：`TODO`
- **依赖**：`DEV-DATA-002`、`DEV-DATA-003`。
- **实施**：实现 `audit_event` 和 `outbox_event`；审计事件使用前序摘要链和规范化 payload；只记录必要元数据，不复制证据原文；发布事务可同库写入审计和 outbox。
- **产物**：迁移、审计追加接口、outbox 仓储。
- **验收**：审计只追加；事件摘要可重算；失败能使业务事务整体回滚。
- **负向检查**：审计插入失败、重复幂等键和篡改 payload 被发现。
- **实现方检查**：事务和摘要契约检查。
- **人工验证**：用户执行事务回滚用例。
- **完成证据**：摘要向量、回滚结果。

## DEV-DATA-008 实现规范化 JSON、UUID、时间和摘要基础库

- **状态**：`TODO`
- **依赖**：`DEV-BOOT-003`。
- **实施**：统一应用生成 UUID；数据库 `timestamptz`/UTC；API ISO 8601 UTC；UI Asia/Shanghai；实现确定性 JSON canonicalization 和 SHA-256；时钟通过 `Clock` 注入。
- **产物**：共享值对象、序列化配置、摘要工具和测试向量。
- **验收**：相同语义输入得到相同摘要；字段顺序和系统默认时区不影响结果。
- **负向检查**：浮点/数字、null、Unicode、时区和数组顺序边界有明确规则。
- **实现方检查**：固定测试向量契约检查。
- **人工验证**：无。
- **完成证据**：测试向量和输出摘要。

## DEV-DATA-009 实现 PostgreSQL 仓储事务边界

- **状态**：`TODO`
- **依赖**：`DEV-DATA-002` 至 `008`。
- **实施**：使用 Spring JDBC/显式 SQL 实现仓储；定义任务锁、发布事务、租约领取和只读查询事务；禁止 controller/Harness 直接访问 JDBC。

- **实现方检查**：编译和 SQL 契约；并发数据库测试由用户执行。
- **人工验证**：用户执行并发与回滚测试。
- **完成证据**：事务清单、用户结果、提交号。
