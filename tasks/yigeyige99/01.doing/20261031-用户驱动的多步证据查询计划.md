## 需求

### ID&标题

用户驱动的多步证据查询计划

### 描述

把当前一次 guidance 内自动执行 3 轮查询，改为由用户聊天动作驱动的一轮查询计划：

- 一次用户动作生成一个最多 5 步的查询计划；
- 步骤支持依赖、参数化绑定和失败隔离；
- 不再自动进入下一轮规划；
- 证据按动作保存快照，先存证据再调初稿模型；
- 初稿失败时证据保留可复用；
- 候选表和选表任务级缓存，`needTableReselection` 时失效重建；
- 聊天框即继续入口，不新增按钮。

## 背景

当前 `EmsDatabaseAssistanceService.collect` 在单次 guidance 内自动 `MAX_ROUNDS=3`，用户无法控制查询节奏，空表会被反复查询；同时 SQL 为单条，无法表达流程定义 → 节点 → 流转的依赖查询。

## 目标

- [ ] 新增查询计划契约：`steps`、`dependsOn`、`bindings`
- [ ] 查询计划模型只输出 steps，初稿模型输出 `needMoreEvidence`/`needTableReselection`
- [ ] 执行引擎支持拓扑顺序、参数化绑定、失败隔离、0 行跳过依赖
- [ ] 一次用户动作只跑一个计划，不自动进入下一轮
- [ ] 先保存证据快照，再调用初稿模型；初稿失败证据保留
- [ ] 候选/选表任务级缓存，`needTableReselection` 失效
- [ ] 单任务串行 + 幂等键
- [ ] 响应返回 `evidenceRound`、`needMoreEvidence`、`needTableReselection`
- [ ] 提示词更新为 steps/bindings 契约
- [ ] 前端显示轮次和继续提示，不新增按钮

## 验收标准

- [ ] 一次动作可执行 4 步依赖计划，按序执行
- [ ] 0 行步骤的依赖步骤跳过，独立步骤继续
- [ ] 绑定只来自指定列且参数化执行，注入用例被拒
- [ ] 初稿 504 后证据仍可复用
- [ ] 连续发送意见不并发执行
- [ ] `needTableReselection=true` 时重建候选表
- [ ] 单任务最多 5 步、单步 30 行
- [ ] 相关单测和编译通过
