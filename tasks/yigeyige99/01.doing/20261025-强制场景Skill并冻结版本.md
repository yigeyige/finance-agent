## 需求

### ID&标题

强制选择业务场景 Skill 并冻结任务版本

### 描述

业务处理任务必须关联业务场景 Skill。界面默认选择“通用业务分析”，直接调用接口时未提供 Skill 必须拒绝。模型提示不得由业务代码写死，应由任务创建时冻结的 Skill 修订与受控系统模板共同构造，并为默认通用场景规划可重复执行的初始化 SQL。

## 背景

- 当前任务允许不选 Skill，并在调用时读取 Skill 的当前可变内容，无法证明多轮分析使用的是同一业务语义。
- 当前代码仍存在业务硬编码提示与粗粒度过滤覆盖 Skill 语义的风险。
- 本切片先建立强制选择、默认 Skill、不可变修订和任务冻结契约，为后续模型调用与决策包分析提供稳定输入。
- 默认“通用业务分析”只负责识别目标、范围、约束、假设、证据、冲突、缺口与建议，不预设系统、表、字段、流程或结论。
- 本轮只完成任务与 OpenSpec 提案，不实施代码或数据库迁移。

## 目标

- [ ] 任务创建强制关联有效业务场景 Skill，界面默认选择通用场景，接口缺失时拒绝
- [ ] Skill 编辑采用不可变修订，任务冻结 Skill 修订、内容摘要与提示模板版本
- [ ] 规划默认通用场景 Skill 的 Flyway 初始化 SQL 与幂等升级规则
- [ ] 模型提示由受控系统模板、业务说明和冻结 Skill 组合，不在业务代码中写死具体场景语义

## 验收标准

- [ ] OpenSpec 明确默认 Skill 的名称、处理方式和完整提示内容
- [ ] OpenSpec 明确旧任务不受后续 Skill 编辑影响，当前默认修订不得直接删除
- [ ] OpenSpec 明确 UI 默认值与后端强校验的双重约束
- [ ] `openspec validate require-versioned-business-scene-skill --strict` 通过
