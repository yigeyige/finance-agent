## 需求

### ID&标题

治理模型调用、证据状态与有界历史上下文

### 描述

每轮业务处理建立独立模型调用尝试，保存该轮产生的全部证据与状态；多轮调用继续使用业务说明、冻结 Skill 和可控大小的历史证据上下文。原始证据必须完整追加保留，但不得把全部原始行一次性塞入模型输入。

## 背景

- 当前跨轮模型调用没有可靠携带此前证据，且存在“证据已入库但最终模型失败”仍被当作已分析证据的语义混淆。
- 单条证据在现有限制下即可达到约 60 万字符，50 条极端情况下约 3000 万字符，直接拼接会超过模型上下文并放大成本与泄露面。
- 本切片采用“原始证据全量留存 + 权威索引 + 确定性压缩 + 分块分析 + 最终汇总”，复用现有上下文压缩的引用、摘要、digest 与 unknown 完整性校验。
- 本切片依赖 `require-versioned-business-scene-skill`；本轮只完成任务与 OpenSpec 提案，不实施。

## 目标

- [ ] 建立模型调用 attempt 与证据状态机，失败不覆盖历史记录
- [ ] 证据追加保存且保留轮次、来源、时点、摘要和完整性信息
- [ ] 设计可配置的 token/字符/行数预算与分块分析策略
- [ ] 明确重试复用证据和必须重新查询的判定条件

## 验收标准

- [ ] 查询成功而最终模型失败时，attempt 为失败且证据标记为待分析，默认不进入决策包
- [ ] 同一 schema/table/purpose 的不同轮证据和冲突均保留，不被“最新覆盖”
- [ ] 超预算时通过确定性截取、引用压缩和分块汇总处理，不静默丢失 unknown 或伪造证据
- [ ] `openspec validate govern-model-attempt-evidence-context --strict` 通过
