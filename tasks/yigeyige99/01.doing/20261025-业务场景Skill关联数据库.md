## 需求

### ID&标题
业务场景 Skill 关联 EMS 数据库并接入表知识

### 描述
业务表知识已沉淀为 JSON（account/activiti_ems/basedata），需要入库并按「数据库连接实例」关联到业务场景 Skill；业务处理界面不再单独选数据库，改为选择已关联数据库的 Skill，模型按 Skill 关联的库查询并注入对应表知识。

## 背景

- `docs/ems-knowledge/table-knowledge/*.json` 已沉淀表知识，但尚未接入运行时。
- `task.business_scene_skill` 目前无数据库关联；`description` 上限 1000 字，装不下表知识。
- `task.ems_database_connection_config` 支持多实例但全局唯一启用（`requireEnabled()`），业务处理无法区分数据库。
- 业务处理第一步 Skill 目前可选，数据库查询用全局启用连接。

## 目标

- [ ] Flyway 新增 `ems_table_knowledge` 表（按 config_id+schema+table 唯一，含 data_status 与 knowledge JSONB）
- [ ] Flyway 新增 `business_scene_skill_database_rel` 表（skill↔数据库多对多）
- [ ] 将现有 3 个 table-knowledge JSON 导入 `ems_table_knowledge`（config_id 指向隆地实例）
- [ ] Skill 增改支持勾选关联数据库（多选），`BusinessSceneSkillContext` 携带 configIds
- [ ] 业务处理创建任务时 Skill 改为必选；模型按 Skill 关联的数据库查询，并注入对应表知识（promptHint）
- [ ] `skill.description` 回归纯业务说明，不再硬塞表知识

## 验收标准

- [ ] 启动后可建 `ems_table_knowledge` 并查到导入的表知识（含「无数据」标记）
- [ ] Skill 编辑页能勾选多个数据库并保存
- [ ] 业务处理未选 Skill 时无法创建任务（必选校验）
- [ ] 模型分析使用所选 Skill 关联的数据库，而非全局启用连接
- [ ] 相关单测/契约验证通过

## 执行记录
