## 需求

### ID&标题

新建业务处理的业务场景下拉框改为展示业务场景 Skill 列表

### 描述

新建业务处理界面（`http://127.0.0.1:5175/#/`）第一步的「业务场景」目前是硬编码的 4 个选项（业务调整/人员变更/审批异常/配置调整），应改为动态展示业务场景 Skill 列表（来自 `business_scene_skill` 表），用户选择后创建任务时关联该 Skill。

## 背景

用户前端手动新建业务处理时，因第一步没有 Skill 选择入口，任务未关联任何 Skill（`task_business_scene_skill` 无记录），导致模型缺少业务知识、premiseType 输出「待核验」、证据查询也不准。业务场景下拉框应展示 Skill 数据，让用户在创建任务前就能选定 Skill。

## 目标

- [ ] 第一步增加「业务场景」下拉框，动态加载并展示业务场景 Skill 列表。
- [ ] 用户选择 Skill 后，`createTask` 传 `businessSceneSkillId`，任务关联该 Skill。
- [ ] 未选择时保持原有通用业务处理能力。

## 验收标准

- 新建业务处理第一步展示 Skill 列表（含「人员配置查询」「审批流程处理」等）。
- 选择 Skill 后创建的任务在 `task_business_scene_skill` 有记录，模型分析使用该 Skill 的 premiseType/description。
- 前端 typecheck 通过。

## 执行记录

- 2026-10-24 确认需求，开始实施。
