## 需求

### ID&标题

审批流程协作附件上限与 BPMN 投影修正

### 描述

修正「审批流程生成-隆地」场景第二轮模型协作的两个问题：

1. `BusinessGuidanceContext` 对 `sceneAttachmentBodies` 的上限是 2，但必读 BPMN 已占 1 个、模型允许请求 2 个，合并后最多 3 个，导致 `sceneAttachmentBodies is invalid` 400。
2. `BpmnStructureProjector` 只解析 XML，而 EMS 的 `.xml` 附件实际是 Activiti model JSON，导致 `[Fatal Error] :1:1` 并回退为 54 字符摘要，模型拿不到 BPMN 结构。

## 背景

“测试3号出差流程”首次分析报 `当前任务信息无法用于模型分析`。诊断日志定位到第二轮上下文构造：
`sceneAttachmentBodies is invalid`。进一步确认：
- 必读 BPMN 1 个 + 模型请求 2 个 = 3，超过上下文上限 2；
- EMS 样例文件 `中艺深圳-退还按金BPMN.xml` 内容是 Activiti model JSON（`childShapes`），XML 投影失败。

## 目标

- [x] `BusinessGuidanceContext` 的场景正文上限改为 3（1 必读 + 2 请求），抽常量并注释来源。
- [x] `BpmnStructureProjector` 支持 Activiti model JSON：内容嗅探、节点/流转/条件/坐标投影，`source` 为空时从节点 `outgoing` 反推。
- [x] 保留标准 BPMN XML 解析路径。
- [x] 新增 `BpmnStructureProjectorTest` 与 `BusinessGuidanceContextTest`。
- [x] 同步 `business-scene-skill-attachment` 规格。
- [x] 重新打包重启并复跑链路，确认不再出现 `sceneAttachmentBodies is invalid` 和 `[Fatal Error]`（已通过；用户手动确认图形整齐）。
- [x] 新增/更新单元测试并通过。
- [x] 修正 BPMN 连线 `dockers`：使用 `route()` 首尾点连接节点边界，避免箭头从网关/任务中心穿过。
- [x] 网关尺寸对齐 EMS 样例（40×40），网关连线改用菱形中心 docker；任务/事件仍用边界点。
- [x] 完全对齐 EMS 样例：任务 100×80、开始 30×30、结束 28×28；开始/结束事件也用中心 docker；网关名称置空。
- [x] 提高初稿模型输出上限（`16384` → `65536`），并在解析失败时记录 `finishReason` 与输出长度。

## 验收标准

- 3 个场景正文允许进入第二轮；4 个仍拒绝。
- Activiti model JSON 能投影出 `processName`、`nodes`、`flows`、`condition`，且不抛 XML 解析错误。
- 标准 BPMN XML 投影行为不变。
- 后端测试通过，重启后“测试3号出差流程”不再报 400。
