## 需求

### ID&标题

- 加固模型主密钥派生与兼容解密

### 描述

- 消除当前模型主密钥按字符串前 32 个字符截断后直接作为 AES Key 的实现缺陷。
- 在内网部署场景下使用简单、可验证的 AES-256 派生方案，新密文带版本标识，已有密文仍可读取。

## 背景

- 现有实现可能因多字节字符得到非法长度的 AES Key，且静默忽略主密钥后续内容；直接替换算法会导致已有模型 API Key 无法解密。

## 目标

- [x] 新密文使用完整主密钥派生的固定长度 AES-256 Key，并带格式版本标识。
- [x] 保持旧格式密文只读解密兼容，不记录主密钥或 API Key。
- [x] 补充多字节主密钥、旧密文兼容和篡改失败测试，并完成编译验证。

## 验收标准

- 任意合规主密钥均得到确定的 32 字节 AES Key，新写密文不会使用截断前缀。
- 已有旧格式密文可继续被同一部署主密钥解密；篡改或格式错误安全失败。
- API Key 明文、主密钥与密文均不出现在日志、接口或错误消息中。

## 执行记录

- 2026-10-09：根据系统设计审查发现的模型主密钥截断缺陷创建任务。
- 2026-10-09：新密文改为 `v2:` 格式并使用完整主密钥 SHA-256 派生 AES-256 Key；旧无前缀密文保留兼容解密路径。相关单元测试、编译和严格规格校验通过。
