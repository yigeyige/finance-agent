## 需求

### ID&标题

业务处理支持上传附件并交给大模型分析

### 描述

新建业务处理时，用户可选择附件；附件内容需要由后端受控提取并作为本次业务处理初稿的模型分析上下文。

## 背景

当前业务处理向导仅将业务标题和说明交给模型，无法利用用户补充的业务材料。附件不能作为浏览器端未受限数据直接拼接到模型请求中，需在后端校验格式、数量和大小，并避免持久化原始附件或在响应、日志中回显其内容。

## 目标

- [x] 在“开始模型分析”前提供可选择、删除和清晰展示的附件入口。
- [x] 后端仅接受受限的文本类附件，提取受限文本摘要并作为初稿模型上下文。
- [x] 附件校验失败或模型调用失败时给出明确中文错误，不创建附件持久化副本。
- [x] 覆盖附件正常、格式/大小/数量越界与无附件兼容路径，并完成前后端构建验证。

## 验收标准

- 用户可在新建业务处理页选择最多 3 个 `.txt`、`.md`、`.csv` 或 `.json` 附件，单个文件不超过 1 MB；可在提交前移除。
- 前端通过 `multipart/form-data` 将附件与已创建任务的初稿请求提交；未选择附件时保持既有 JSON 初稿接口行为。
- 服务端拒绝不支持的格式、空文件、超出数量或大小的文件；原始内容不写入数据库、日志或响应。
- 模型仅接收总量受限的 UTF-8 文本和文件名，并在提示词中明确该内容是待核验的用户提供材料。
- 相关后端测试、前端构建与 OpenSpec 严格校验通过；本地启动和人工验收由用户执行。
