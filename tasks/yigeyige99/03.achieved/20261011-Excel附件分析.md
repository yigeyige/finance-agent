## 需求

### ID&标题

业务处理支持 Excel 附件大模型分析

### 描述

新建业务处理时允许上传 Excel 附件，后端使用用户授权引入的 FastExcel 解析工作表数据，并将受限文本投影提交给大模型分析。

## 背景

现有附件初稿分析仅支持 UTF-8 文本。Excel 为二进制工作簿，不能直接作为当前文本模型客户端输入；需在服务端解析为受限行列文本，同时避免加载无界数据或持久化原始文件。

## 目标

- [x] 引入并锁定与 Java 17 兼容的 FastExcel 依赖。
- [x] 支持 `.xls`、`.xlsx` 附件的流式受控解析，将工作表、表头和单元格文本投影交给模型。
- [x] 限制工作表数量、行列数、单元格文本与总模型文本，拒绝损坏、加密或超限工作簿。
- [x] 补充 Excel 正常、损坏和边界测试，并完成前后端编译验证。

## 验收标准

- 用户可在现有附件入口选择 `.xls`、`.xlsx`；无附件及原有文本附件行为保持不变。
- 服务端仅将经 FastExcel 解析的受限文本投影用于本次模型初稿，不保存工作簿或解析文本。
- Excel 解析失败或超出结构限制时返回中文业务错误，不调用模型。
- 相关单元测试、后端编译、前端生产构建与 OpenSpec 严格校验通过；本地启动和人工验证由用户执行。
