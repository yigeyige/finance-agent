## 需求

### ID&标题

20261010 修复本地登录未执行数据库迁移

### 描述

本地前后端启动后，`admin` 登录接口命中但返回 401；修复后首次登录工作台的左侧菜单仍需刷新才显示。启动流程应在后端启动前执行项目 Flyway 迁移，并在登录跳转后同步工作台身份状态。

## 背景

只读数据库检查确认当前库不存在 `iam.user_password`，导致默认管理员没有密码凭据。现有 `scripts/start-local.ps1` 会加载 `.env` 并启动服务，但不执行 `scripts/flyway-migrate.ps1`；后者也未自行加载 `.env`，所以不能作为可靠的单独本地启动链路。

## 目标

- [x] 本地启动脚本在后端启动前使用同一进程环境执行 Flyway 迁移。
- [x] 迁移失败时不启动后端和前端，并且不输出敏感配置。
- [x] 应用迁移后验证默认管理员的登录接口可成功建立会话。
- [x] 登录成功切换工作台时立即同步根组件身份，显示左侧权限菜单。

## 验收标准

- `scripts/start-local.ps1` 在端口空闲时先完成迁移，再后台启动后端和前端。
- 已执行迁移的环境再次启动保持幂等，且不重复写入管理员凭据。
- 迁移后的 `admin` 正确凭据返回当前身份和会话 Cookie；错误凭据仍返回统一 401。
- 脚本静态检查、相关后端测试和前端构建通过。

## 执行记录

- 2026-10-10：根据登录 401 故障创建任务；只读检查确认数据库缺少 `iam.user_password`，根因是本地启动脚本未执行 Flyway 迁移。
- 2026-10-11：启动脚本复用迁移入口并按退出码失败关闭，实际将数据库从 V14 迁移到 V16；正确管理员登录返回 200 和会话 Cookie，错误密码返回 401。登录后的工作台根组件同步身份缓存，首次进入即可渲染左侧权限菜单；前端类型检查与生产构建、迁移静态校验、启动脚本语法检查和认证相关后端测试均通过。
