## 需求

### ID&标题

业务场景 Skill 字段调整：业务名称改场景名称、去掉处理方式/业务场景、业务说明改调查提示词、新增决策包提示词、弹窗与编辑框调大。

### 描述

对「业务场景 Skill」的字段结构和维护界面做收敛：
1. 「业务名称」更名为「场景名称」。
2. 去掉 Skill 的「处理方式」和「业务场景」两个字段（后续方案不再使用）。
3. 「业务说明」更名为「调查提示词」。
4. 新增「决策包提示词」字段。
5. 新建/编辑弹窗加宽，两个提示词字段的编辑框加大。

## 背景

- 当前 `task.business_scene_skill` 表含 `handling_type`、`premise_type` 字段，模型上下文 `BusinessSceneSkillContext` 也携带这两个字段，但后续方案不再依赖它们。
- `description` 实际承担的是「调查提示词」（固定提示词）职责，且后续业务决策包生成需要单独的「决策包提示词」，需要拆分为两个独立字段。
- 现状弹窗宽度 560px、调查提示词 textarea 4 行，编辑长提示词不便。

## 目标

- [x] 后端 Skill 数据模型去掉 `handlingType`/`premiseType`，`description` 改为调查提示词，并新增决策包提示词字段。
- [x] Flyway 迁移同步表结构与既有数据（含字段重命名/新增列）。
- [x] 后端请求/响应/服务/控制器与模型上下文同步新字段结构。
- [x] 前端契约与 Skill 维护页（列表、表单、弹窗）同步新字段结构。
- [x] 前端去掉对 Skill `premiseType`/`handlingType` 的展示依赖，并调宽弹窗、加大两个提示词编辑框。

## 验收标准

- [x] 模型分析链路中注入的 sceneSkill 不再携带 `handlingType`/`premiseType`，改为两个提示词字段。
- [x] 后端编译通过、相关测试通过；前端类型检查/构建通过。
- [x] 弹窗明显加宽，两个提示词 textarea 行数加大且可正常滚动。
