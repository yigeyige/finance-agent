## 需求

- 在 `scripts/` 下提供一个可直接启动前后端本地 local 环境的脚本，后续无需手工逐项导入环境变量并分别启动。

## 背景

- 后端运行依赖仓库根目录 `.env` 中的数据库等变量；未导入时身份接口会失败，进而使前端无法加载菜单。

## 目标

- [x] 通过一个 PowerShell 脚本读取 `.env` 并启动后端和前端。
- [x] 防止端口已被占用时重复启动，并给出可访问地址和日志位置。
- [x] 提供静态语法检查和启动链路验证。

## 验收标准

- 从仓库任意工作目录执行脚本后，后端获得 `.env` 中的进程环境变量，前端可通过本地代理访问后端。
- 前端和后端已运行时再次执行不产生重复实例。
- 脚本不输出或写入 `.env` 中的敏感值。
