## 需求

### ID&标题

- 接入大模型业务交互并明确人工确认边界

### 描述

- 当前业务向导虽然简化了输入，但调查方案和决策包仍由固定规则生成，页面看不出大模型何时参与。需要把模型真实接入方案生成与证据分析，并明确展示模型状态、产出和人工确认边界。

## 背景

- 项目已有 DeepSeek AgentScope 适配器和 Stub 配置，但尚未注册到业务调用链。
- 前端当前使用固定规则生成调查目标，证据页和决策包也没有独立的模型分析步骤。
- 真实模型调用必须限制输入范围、输出结构、超时和预算；Stub 模式不得冒充真实模型。

## 目标

- [x] 范围确认后通过后端模型服务生成推荐调查方案和备选方案。
- [x] 证据就绪后通过后端模型服务生成业务摘要、风险判断和后续建议。
- [x] 页面清晰展示模型处理中、模型产出、模型模式和人工确认阶段。
- [x] 模型失败时安全失败，并提供不误导用户的重试或确定性回退说明。
- [x] 完成后端测试、前端类型检查、构建和核心流程验证。

## 验收标准

- 调查方案不再由前端固定规则直接生成，而是来自受控模型交互接口。
- 决策包组装前必须先完成一次证据分析，并把模型结论纳入业务摘要和建议。
- Stub 环境明确显示“本地模拟模型”，真实模型环境显示实际模型名称。
- 模型请求不包含未授权的证据字段，响应按严格结构解析且不展示推理过程。
- Maven 测试、前端类型检查、生产构建和 OpenSpec 严格校验通过。
