# 使用 MyBatis-Plus ASSIGN_UUID 统一 UUID 生成

## 需求

### ID&标题

`20260926-assign-uuid-ids` 使用 MyBatis-Plus `ASSIGN_UUID` 统一现有 UUID 主键生成策略。

### 描述

当前持久化实体使用 `IdType.INPUT`，需要保留 PostgreSQL `uuid` 主键结构，同时改为由 MyBatis-Plus 自动生成 UUID。由于 `ASSIGN_UUID` 默认返回字符串，持久化 Entity 主键使用 `String`，领域层继续使用 `UUID` 并通过通用映射转换，避免各仓储重复生成标识。

## 背景

数据库现有主键、外键均为 `uuid` 类型，不迁移数据库字段类型，不引入额外分布式 ID 框架。MyBatis-Plus 3.5.17 已作为项目持久层基线。

## 目标

- [x] 将持久化实体主键策略统一为 `IdType.ASSIGN_UUID`。
- [x] 配置并验证项目级通用 UUID 标识生成能力，兼容持久化字符串主键、现有数据库 UUID 字段和领域对象。
- [x] 补充生成策略和仓储写入验证，保持现有数据库迁移与业务行为不变。
- [x] 更新 OpenSpec、文档和执行记录，完成编译与测试验证。

## 验收标准

- 所有 MyBatis-Plus 持久化实体的主键不再使用 `IdType.INPUT`，统一使用 `ASSIGN_UUID`。
- 新增实体未设置主键时，Mapper insert 可自动生成 UUID；显式提供主键时仍保持兼容。
- 不新增 Hutool、Leaf 或其他分布式 ID 依赖，不修改既有数据库迁移脚本。
- 相关单元测试、编译和完整测试通过。
