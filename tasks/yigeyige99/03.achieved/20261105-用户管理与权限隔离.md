# 用户管理与权限隔离

## 需求

### ID&标题

用户管理与权限隔离

### 描述

平台管理员管理用户、角色和密码；普通用户仅能访问四个业务菜单，按发起人访问自己的任务，所有人共享业务场景但普通用户只可维护自己创建的场景；异常堆栈按用户隔离。

## 背景

现有角色为 OPERATOR、VIEWER、PLATFORM_ADMIN，任务列表已有发起人过滤，业务场景和异常堆栈尚未满足本次权限边界。新库无旧 OPERATOR/VIEWER 账号。固定登录账号 admin 在用户管理中完全不可操作。

## 目标

- [x] 管理员可新增、编辑、停用和重新启用用户并设置或重置密码，固定 admin 账号及最后一个有效管理员受到保护。
- [x] 角色收敛为 PLATFORM_ADMIN、PLATFORM_USER，菜单与任务操作遵守角色和任务归属。
- [x] 业务场景全员可见可选用，普通用户仅维护自己创建的记录，管理员可维护全部。
- [x] 异常堆栈普通用户仅见本人最近异常，管理员见全站最近异常，无用户异常仅管理员可见。

## 验收标准

- 非管理员直接请求用户管理接口或他人任务、场景修改接口被拒绝。
- 停用与降权对现有会话立即生效；停用保留任务和场景。
- 普通用户菜单恰为业务处理、任务列表、业务场景、异常堆栈；管理员可见全部菜单。
- 静态检查、前端编译与相关后端测试通过；本地启动和手工验收由用户执行。

## 手工验收（操作人执行）

- 启动本地环境并确认 V55 迁移执行；用 admin 新增普通用户、修改、重置密码、停用及启用，确认 admin 本身没有操作入口。
- 用两个普通用户分别创建任务、业务场景和异常；核对四个菜单、跨用户任务拒绝、场景共享选择与作者维护限制，以及异常仅显示本人最近一条。
- 用管理员核对全部菜单、全部任务与场景、全站最近异常；停用一个已有业务数据的用户后确认业务记录仍存在，原会话立即失效。
