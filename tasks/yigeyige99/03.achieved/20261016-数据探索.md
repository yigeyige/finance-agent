## 需求

### ID&标题

- 数据探索功能

### 描述

- 在工作台左侧增加“数据探索”菜单，参照 SQL 查询平台布局，为平台管理员提供 EMS 数据库的受控只读查询、表目录和字段查看能力。
- 首版不增加写操作、导出、持久化查询历史或收藏；复用已启用的 EMS 数据库连接与单条 SELECT 守卫。

## 背景

- EMS 数据库配置已支持唯一启用的 MySQL 只读连接、连接测试、超时、最大返回行数和密码加密保存。
- 现有业务处理模型只能在特定流程中使用受控查询，管理员需要独立页面直接探索结构和有限查询结果。
- 用户已确认先实现核心只读工作台，运行环境由用户自行启动和人工验证。

## 目标

- [x] 平台管理员可在“数据探索”页面查看当前启用数据源、允许业务库表目录和字段结构。
- [x] 平台管理员可执行受控单条 SELECT，并查看受限的查询结果、行数与耗时。
- [x] 未启用连接、无权限、无结果、查询不合规和查询失败均有安全且清晰的界面反馈。
- [x] 首版不提供写操作、导出、查询历史或收藏，且不泄露连接信息、密码、原始驱动错误或 SQL 日志。
- [x] 后端自动化测试、编译、前端类型检查和生产构建通过。

## 验收标准

- “数据探索”仅对平台管理员可见且服务端拒绝非管理员访问。
- 页面仅列出允许的 EMS 业务库，排除系统库、`claim`、`xxljob` 与 `arch_db`；可按表名或中文注释搜索并查看字段结构。
- 查询接口仅接受已由现有 Guard 验证的单条 SELECT，沿用启用连接的超时、最大行数、列数和单元格投影限制。
- 页面使用既有 Vue 2、Element UI 与工作台暖白卡片样式，不引入第三方 SQL 编辑器依赖；行数选择不超过 100。
- 通过定向后端测试与编译、前端类型检查和生产构建；用户完成本地运行与人工验证。
