## 需求

### ID&标题

- 精简方案协作界面与生成后模型修改

### 描述

- 去除业务处理向导中重复的副标题和说明文字，保留必要的字段标签和操作反馈。
- 合并“业务对象”与“系统中的业务对象”为一个处理对象输入，后台仍按既有前提和范围契约保存。
- 业务方案仅保留推荐方案，不展示或提交备选方案。
- 将模型聊天协助与业务方案置于同一个区域，并支持方案生成后继续让模型修改推荐方案；在尚未执行时将修改同步到已生成方案。
- 在右侧技术明细中补充模型名称、模式、调用耗时、Token 数及可用的推理强度。
- 将对象与处理范围、推荐方案与模型协助调整为上下布局，使操作顺序清晰呈现。
- 压缩对象范围表单的短字段布局，并在下方将推荐方案与模型协助并列展示。
- 左侧栏增加任务列表与业务场景 Skill 菜单，并提供对应页面；业务场景 Skill 列表支持新增、编辑和删除。
- 将任务列表和业务场景 Skill 列表统一为通用数据表格样式，避免内部状态码、列挤压和窄屏错位。

## 背景

- 当前两步向导已经可由模型预填并直接生成方案，但副标题、引导语、对象字段与协作区信息密度偏高。
- 聊天区与方案编辑器分离，且在生成方案后被禁用，不符合管理员围绕推荐方案持续沟通、再更新方案的使用方式。
- 后端模型元数据已具备模型名称、模式、Token 数和耗时；推理强度并非当前固定契约字段，前端需按可选字段安全展示。

## 目标

- [x] 精简首屏与模型协作步骤中的重复副标题、说明和提示语。
- [x] 以单一处理对象字段承接前提与范围所需对象标识。
- [x] 将方案与聊天整合为一个协作区，仅维护一条推荐方案。
- [x] 支持在方案生成且尚未执行时，经模型聊天修改并持久化推荐方案。
- [x] 展示安全的模型调用技术明细，并完成前后端验证。
- [x] 支持管理员维护业务场景 Skill，包括新增、编辑、删除与列表刷新。
- [x] 使用清晰、通用的数据表格展示任务与业务场景 Skill 列表。

## 验收标准

- 向导保留两步和必要操作按钮，不再显示重复副标题、重复说明或备选方案输入。
- 管理员只填写一次处理对象，系统可成功保存前提、范围并生成方案。
- 模型聊天位于推荐方案区域，生成方案后仍可用；修改后页面与已生成步骤保持一致。
- 技术明细显示模型名称、模式、调用耗时、Token 数，接口返回推理强度时才显示该项。
- 业务场景 Skill 列表可新增、编辑、删除，删除后列表不再显示已删除条目。
- 任务和业务场景 Skill 列表使用一致的表头、列宽、状态与空态样式，在窄屏下可正常横向查看。
- 前端类型检查、生产构建、相关后端测试和 OpenSpec 校验通过。
