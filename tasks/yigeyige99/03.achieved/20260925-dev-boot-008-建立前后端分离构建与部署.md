# 建立前后端分离构建与部署

## 背景

本任务来自财务共享智能运维 Agent 开发任务基线中的 `DEV-BOOT-008`，用于建立前后端分离构建与部署。原任务曾验证单 JAR/单应用镜像，但该形态不符合目标部署边界，本次在原任务上修订为前端静态镜像与后端 API 镜像独立发布。方案追踪：主方案第 12 节。

## 目标

- [x] 前端构建产物与后端 JAR 独立交付，后端 JAR 不包含前端静态资源。
- [x] 建立独立的前端 Nginx 镜像和后端 Java 镜像，均使用非 root、只读优先文件系统和健康检查。
- [x] 两个镜像使用同一版本号，不提供 Compose，不挂载 Docker socket。
- [x] 交付并核对以下产物：后端可执行 JAR、前端静态产物、两份 Dockerfile、Nginx 配置、`.dockerignore`、分离启动说明。

## 验收标准

- 同一版本生成前端静态产物、后端 JAR、前端镜像和后端镜像。
- 后端 JAR 不包含 `BOOT-INF/classes/static/index.html`；前端镜像包含编译后的 `index.html`。
- 镜像不包含源码、npm cache、Maven cache、密钥或 `.env`。
- 负向检查：容器以 root 运行、要求 Docker socket 或依赖 Compose 时不通过。
- 实现方检查：前端/后端构建和两个镜像构建；不启动长期运行容器。
- 人工验证：用户分别启动前端和后端并检查页面、API/健康端点及网关路由。
- 完成证据：制品摘要、镜像元数据、静态负向检查和用户验证结果。
