## 需求

### ID&标题

审批流程生成提示词与 act_id 匹配修正

### 描述

修正「审批流程生成-隆地」场景在“测试2号出差流程”验证中暴露的问题：

1. 新流程命名口径统一为业务标题/业务说明，附件中的审批流程名称仅作参考，不覆盖目标流程名。
2. 角色码查询改用 `basedata.sys_value_set_item` + `basedata.sys_value_set_item_lang`，`LANG_CODE='zh-TW'`，按名称匹配 `VSI_KEY`，不再使用不存在的 `VSI_NAME`。
3. 审批规则只在附件提供审批金额范围时按 EMS 契约生成；按起草角色分档时走 BPMN 排他网关，不生成空壳 `审批规则.json`。
4. `act_id` 按用户约定（单据起草 `act_010`、部门负责人 `act_11` 等）并从 `activiti_ems.psc_act_config` 的 `act_id/act_name` 字典匹配；无法匹配时按约定给值并列入待补。

## 背景

2026-11-03 按“测试2号出差流程”走通链路后，初稿与流程文件均标记 `NEEDS_REPAIR`。后端日志与源库核对确认：

- 模型用任务标题查 `psc_act_re_model` 得到 0 行，但新流程生成本就不应以附件名称为准；命名口径需要统一。
- 模型生成 `SELECT ... VSI_NAME ... FROM basedata.sys_value_set_item`，该列不存在，角色码步骤失败。
- 模型输出的 `approvalRules` 使用 `draftRole/amountRange` + `nodeId/nodeName`，与转换器只保留的 EMS 字段（`workflowLineKey`、`applyLineValue`、`applyAmountMin/Max`、`currency`）不一致，生成了空规则文件。
- `psc_act_config` 去重后 769 条 `act_id/act_name`，可注入模型上下文辅助匹配。
