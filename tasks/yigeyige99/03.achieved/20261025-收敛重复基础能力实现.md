## 需求

### ID&标题

收敛重复基础能力实现（SHA-256 与 JSON 序列化）

### 描述

对后端进行只读审查后发现两处"重复造轮子"：SHA-256 摘要散落 5+ 处重复实现、JSON 序列化散落 13 处 `JsonMapper.builder().build()` 各自新建实例。本任务将这些收敛到项目已有的统一基础能力，消除重复并落实编码规范"复用优先 / 避免重复造轮子"。

## 背景

2026-10-25 按用户要求检查代码中的 Java 原生写法与可替换点，确认：

1. **SHA-256 重复**：项目已有统一工具 `shared/domain/Sha256Digest.hex()`，但 `storage/infrastructure/LocalTemporaryObjectStorageGateway`、`harness/infrastructure/ControlledWorkspaceManager` 各自重写 `sha256()` + 手写 `String.format("%02x")` 转十六进制；`harness/application/AllowedContext`、`harness/application/DeterministicModelStub`、`modelconfig/infrastructure/AesGcmModelApiKeyCipher.derive()` 直接内联 `MessageDigest.getInstance("SHA-256")`。
2. **JSON 序列化重复**：项目已有 `shared/domain/CanonicalJsonCodec`（严格解析 + canonical 编码，用于审计摘要），但业务代码散落 13 处 `JsonMapper.builder().build()` 各自新建实例；`harness/infrastructure/JacksonAgentStateCodec` 甚至用 `new ObjectMapper()` 绕过 Spring 统一 Jackson 配置。

规范依据：`.codex/skills/backend-coding-standards/SKILL.md` 核心原则 5/7、通用工具类选择（JSON 使用统一序列化配置、编码/摘要复用成熟能力）。

## 目标

- [x] 收敛 SHA-256：全项目摘要逻辑仅保留 `Sha256Digest` 一处实现，手写 `String.format("%02x")` 改为 Java 17 `HexFormat`
- [x] 收敛 JSON：业务序列化统一复用单一 `JsonMapper` 实例（新增 `JsonCodec`，不引入新依赖），严格解析复用 `CanonicalJsonCodec.parse`
- [x] JacksonAgentStateCodec 保持不变（Spring Boot 4 无自动 `ObjectMapper` Bean，保留默认构造器，见 design.md）

## 验收标准

- [x] 全项目仅 `CanonicalJsonCodec`（审计摘要专用）与 `JsonCodec`（业务序列化）两处 JsonMapper 定义，不再有散落的 `JsonMapper.builder().build()`
- [x] 全项目仅 `Sha256Digest` 一处 SHA-256 摘要实现，不再有手写 `String.format("%02x")` 或内联 `MessageDigest` 摘要（`AesGcmModelApiKeyCipher.derive` 为密钥派生、digest bytes 作 AES 密钥，非摘要展示，保留）
- [x] `mvn compile` 通过；本次改动相关 29 个单元测试全部通过
