## 需求

### ID&标题

业务决策包：业务处理证据累积与一键生成决策包

### 描述

业务处理过程中，每轮模型思考生成的关联证据目前只展示最新一轮——`guideBusinessHandling` 每次调用都会重新 `collect` 证据（从空列表开始），而 `guidance_draft` 前端读的是最新一份，导致跨轮证据不累积。

需要：1）证据跨轮累积保存到证据工作区；2）管理员点击"生成业务决策包"时，把累积证据 + 业务处理结论固化生成一份可查看的决策包。

## 背景

（2026-10-24 与用户 grill 对齐后确定的设计结论）

- 方向：业务处理侧证据工作区累积 + 用户点击"生成业务决策包"时装配（分层 Y 方案），不接入 packet 包的复核/发布/交接状态机。
- 现状：`BusinessModelInteractionService.guideBusinessHandling` 每次调用重新 `collect`；`task.guidance_draft` append-only 但读最新；packet 包（`PacketDraftAssembler` 等）绑定 scope/runtimeBundle + 状态机，与本场景无关。
- 关键决策：
  - 业务决策包内容 schema = 三块：标识（packet_id/task_id/revision/created_at）+ 业务处理主体与结论建议（BusinessHandlingDraft 全字段）+ evidence（去重合并后）。
  - evidence 语义选 C：工作区追加保留过程（带轮次），生成决策包时按 `(schema, table, purpose)` 去重保留最新。
  - 决策包 evidence 独立上限 50 条；草稿单轮仍限 10。
  - 决策包 evidence 权威来源 = 工作区去重结果，草稿单轮 evidence 不进决策包。
  - 轮粒度 = 每次 `guideBusinessHandling` 调用。
  - 无草稿点生成 → 拒绝并提示；重复生成内容摘要相同 → 跳过，否则 revision+1、旧版保留。
  - 证据工作区随 task 存续不自动清空；`round_no` 用时间戳保证不冲突。
  - `guidance_draft` 保留现状不强行去冗余。
  - 处理过程中证据面板一并切累积视图。

## 目标

- [x] 证据工作区累积每轮证据（append-only，带轮次）
- [x] 生成业务决策包：读工作区 + 最新草稿，evidence 去重合并，落库 revision 递增
- [x] 后端接口：生成决策包、查看决策包、查看累积证据
- [x] 前端：业务处理页证据面板切累积视图 + "生成业务决策包"按钮 + 决策包查看

## 验收标准

- [x] 连续多轮业务处理后，证据工作区按轮追加，前端证据面板展示累积（非仅最新轮）
- [x] 点击生成决策包：evidence 按 `(schema, table, purpose)` 去重保留最新，条数不超过 50
- [x] 内容未变时重复生成不新增 revision；变化时 revision+1、旧版可查
- [x] 无业务处理草稿时点生成被拒绝并给出提示
- [x] 后端构建通过，前端构建通过
