## 需求

### ID&标题

定时调度清理任务、快照、日志、决策包及附件

### 描述

每周日 02:00（Asia/Shanghai）清理超过 30 天的业务和运行记录，不按任务或投递状态豁免；配置性数据保留。数据库各表优先以 `updated_at` 判定，缺失时采用 `created_at` 或明确的业务时间。清理受控 Workspace、临时对象和应用日志目录，即使当前目录没有业务调用也纳入，防止遗漏；Java 调试日志仍供 Agent 直接读取。平台管理员可在前端只读查看清理日志。方案须完整列出可清理表、保留表、附件和日志目录，供用户检查。

后续调整：导航名称改为“调度任务”；页面左侧显示任务列表，右侧显示所选任务最新一次调度日志，并可修改每周执行的星期和时分。默认仍为周日 02:00（Asia/Shanghai），新设置重启后保留。

2026-11-05 页面验收调整：频率扩展为每天、每周、每月；右侧去掉重复的任务名称，Java 类名与调度设置同一行展示，缩小空日志区域留白。

## 背景

当前附件、生成产物主要存在 PostgreSQL；受控 Workspace 和 local/test 临时对象存储另有文件目录。Logback 当前仅输出控制台，本地启动脚本按启动时间生成 stdout/stderr 文件，持续运行时单文件可能增长。清理需要处理外键依赖、审计事件禁止删除触发器及应用日志轮转。

## 目标

- [x] 确认完整的表与文件目录清理清单及排除清单。
- [x] 实现可配置调度的 30 天到期清理和依赖数据处理。
- [x] 实现应用日志轮转、旧日志文件清理及可供 Agent 读取的调试输出。
- [x] 提供平台管理员调度任务页面及只读运行日志。
- [x] 提供左侧调度任务列表、右侧最新日志与可持久修改的执行时间。
- [x] 支持每天、每周、每月频率并调整调度任务页的紧凑布局。

## 验收标准

- OpenSpec 方案逐表列出清理依据、外键影响及配置数据排除项，列出附件、Workspace、日志目录的来源与路径。
- 到期清理不按状态豁免；本周调度失败可从清理日志看到错误，下次调度可继续处理。
- 后端应用日志按日期及大小轮转，保留 30 天；调试输出仍可从本地日志文件读取。
- 平台管理员可查看清理运行日志，其他角色不可访问。
- 调度时间修改后立即按新设置安排下一次执行；重启后保持，非管理员不能修改。
- 仅运行静态检查、编译测试和相关自动化验证；本地环境由用户启动并手动验收。
