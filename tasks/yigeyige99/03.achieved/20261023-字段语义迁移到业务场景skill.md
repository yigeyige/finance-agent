## 需求

### ID&标题

将审批配置字段语义从代码提示词提取到业务场景 Skill，并修复查询规划阶段 Skill 提示词注入

### 描述

1. 上一轮修复把 `basedata.t_audit_configuration` 的字段语义（`EMP_IDS` 存 USERCODE 等）写死在 `DeepSeekBusinessModelClient` 的提示词 instruction 里，属于业务知识，不应硬编码在代码通用指令中。应提取到业务场景 Skill 的 description（可 UI 配置的固定提示词）。
2. 现有 `databaseQueryInput` 在查询规划阶段（选表、生成 SQL）只把 `sceneSkill.name` 注入模型输入，未注入 `description`，导致 Skill 的固定提示词在查询规划阶段失效。

## 背景

业务场景 Skill（`BusinessSceneSkill`）的 description 是"可 UI 配置的固定提示词"，但目前查询规划阶段（`selectRelevantTables`/`planEmsDatabaseQuery`）只注入 skill name，不注入 description；只有最终生成初稿阶段（`guidanceInput`）才注入完整 description。导致业务知识只能写死在 instruction 里才能生效。

## 目标

- [x] `databaseQueryInput` 将 sceneSkill 完整投影（name、description、handlingType、premiseType）注入查询规划输入。
- [x] 从 `selectRelevantTables`、`planEmsDatabaseQuery` 的 instruction 中移除写死的字段语义。
- [x] 将字段语义写入业务场景 Skill 的 description（通过 API 更新）。
- [x] 从 instruction 中移除全部表定位知识（人员账号/员工/审批/角色/组织表），通过 SQL 更新两个 Skill 的 description，并落盘 SQL 脚本。

## 验收标准

- 查询规划阶段模型输入包含 sceneSkill 的 description。
- instruction 不再包含 `t_audit_configuration` 的字段语义细节。
- 复测 guidance 仍能查到 ZENGLINGRUI 的 15 条审批配置（字段语义经 Skill description 生效）。
