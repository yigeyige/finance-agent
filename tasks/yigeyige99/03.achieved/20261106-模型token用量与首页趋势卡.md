## 需求

### ID&标题

模型 token 用量采集与首页 30 天趋势卡片

### 描述

- 后端记录每次真实（LIVE）模型调用的 token 用量，并按用户归属。
- 提供固定 30 天用量的只读接口：普通用户看本人，平台管理员看全平台总量。
- 首页右栏新增 token 用量卡片（总量 + 30 天折线），页面改为左 2/3 三步指南 + 右 1/3 用量卡。

## 背景

当前 token 只在每次模型调用的 `BusinessModelCallMetadata` 中返回，前端对话组件消费过一次即丢弃；`BudgetCounter` 是任务内内存计数，数据库无 token 字段，也没有任何用量查询接口。一次业务处理初稿最多触发 4 次真实调用（选表、查询规划、初稿两轮），其中选表与查询规划当前不返回元数据，无法计量。

## 目标

- [x] 后端补齐选表与查询规划调用的元数据返回，统一在模型客户端装饰器记录用量
- [x] 新增 Flyway 迁移与用量表，记录用户、任务、模型、mode、tokens、发生时间
- [x] 新增 30 天用量只读接口（个人 / 全平台按角色区分），并同步 OpenAPI 契约
- [x] 首页右栏新增 token 用量卡（ECharts 5.6 按需引入，含 5 分钟缓存与失败降级）
- [x] 后端最小测试（聚合、权限、写入失败容错、迁移）与前端类型检查/构建通过

## 验收标准

- 每次 LIVE 模型调用写入一条用量记录；STUB 调用不写入；写入失败时模型调用结果不受影响。
- 普通用户调用用量接口只返回本人数据；平台管理员返回全平台数据；未登录被拒绝。
- 接口固定返回最近 30 个自然日（Asia/Shanghai，含今天），缺失日期补 0。
- 首页显示用量总量与 30 天折线；无数据时显示 0 与空折线；接口失败显示“用量暂不可用”且不影响其他区块。
- `mvn test`（相关用例）、`npm run typecheck`、`npm run build` 通过。
