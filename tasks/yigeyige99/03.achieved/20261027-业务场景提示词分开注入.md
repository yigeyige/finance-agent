## 需求

### ID&标题

业务场景提示词分开注入：调查轮次只注入调查提示词，决策包提示词与调查提示词互不影响。

### 描述

1. 创建任务勾选业务场景后，调查轮次（初稿/修订、EMS 选表、查询规划）的模型上下文只注入「调查提示词」，不再混入「决策包提示词」。
2. 「决策包提示词」保留在场景 Skill 上下文（`BusinessSceneSkillContext`）中，作为后续决策包模型分析的注入点；本次决策包生成不调用模型，暂不消费该提示词。

## 背景

- 业务场景 Skill 已调整为「调查提示词」和「决策包提示词」两个字段。
- 当前 `DeepSeekBusinessModelClient` 与 `StubBusinessModelClient` 在调查阶段把两个提示词都注入 `sceneSkill`，导致两类提示词混用、互相影响。
- 决策包生成当前为纯草稿+证据组装，不调用模型，因此决策包提示词暂无消费方。

## 目标

- [x] 调查阶段的 `sceneSkill` 上下文只注入场景名称与调查提示词。
- [x] 决策包提示词字段保留在场景上下文，供后续决策包模型分析复用。
- [x] 彻底移除草稿、任务前提、前端与提示词模板中的 `handlingType`/`premiseType`。
- [x] 同步相关 spec。

## 验收标准

- [x] 初稿/修订、选表、查询规划注入的 `sceneSkill` 不含 `decisionPacketPrompt`，仅含 `name` 与 `investigationPrompt`。
- [x] 业务处理草稿与任务前提的请求响应不再含 `handlingType`/`premiseType`。
- [x] `GUIDE_HANDLING` 提示词模板不含 `handlingType`/`premiseType`。
- [x] 后端编译、相关测试、前端类型检查与构建通过。
