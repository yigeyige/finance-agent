## 需求

### ID&标题

- 修复数据探索空表注释

### 描述

- 数据探索页面读取表目录时出现“表注释格式无法识别，请稍后重试”。
- 允许 MySQL 表和字段没有注释时以空文本正常展示，同时继续拒绝缺失或非字符串的异常接口字段。

## 背景

- EMS 业务库存在未设置 `TABLE_COMMENT` 的表；后端会将其规范为空字符串。
- 前端当前复用非空字符串校验器解析元数据注释，导致合法的空字符串使整个目录无法展示。

## 目标

- [x] 元数据注释为空字符串时，数据探索目录和字段结构可正常解析并展示。
- [x] 注释字段缺失或类型异常时，前端仍保留安全的契约错误提示。
- [x] 相关前端类型检查、生产构建和定向解析验证通过。

## 验收标准

- 对 `{ schema, table, comment: "" }` 目录项可成功解析。
- 对 `{ name, type, comment: "" }` 字段项可成功解析。
- 对 `comment: null`、缺失 `comment` 或数值类型仍抛出格式错误。
- 不改变后端 SQL、权限、只读执行边界或数据探索其他接口契约。

## 执行记录

- 2026-10-16：根据用户人工验证反馈定位到前端将合法空注释误判为格式错误；创建 OpenSpec 变更 `fix-data-exploration-empty-comments`。
- 2026-10-16：调整表和字段注释的运行时契约校验，允许空字符串但继续拒绝 `null`、缺失和非字符串值；未变更后端查询、权限或只读 SQL 边界。
- 2026-10-16：验证通过：内存编译的定向元数据契约验证、`npm run typecheck`、`npm run build`、`openspec validate fix-data-exploration-empty-comments --strict`。Vite 已运行，用户刷新页面即可人工复验。
