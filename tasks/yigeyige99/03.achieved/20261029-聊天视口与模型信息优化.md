## 需求

### ID&标题
自定义需求：业务处理页标题、聊天视口高度与模型调用信息优化。

### 描述
参考任务列表增加“业务处理”小标题；聊天尽量占满可用高度，输入和“发送”按钮同排；移除“等待业务说明”；顶部紧凑展示当前模型及 Token 等信息，可同步修改后端。

## 背景
沿用暖白橙色与正常字号，不改左侧菜单。已有 guidance.metadata 提供模型名、tokens 和 latencyMillis，统计仅代表最近一次建议生成调用，不包含选表/查询规划/失败调用/决策包等全任务消耗。新增安全的只读模型摘要供初次调用前展示，不暴露管理员连接详情。

## 目标
- [x] 增加业务处理页标题，聊天按实际顶部位置填充视口。
- [x] 输入与发送同排，移除等待状态并紧凑展示模型及最近调用统计。
- [x] 新增只读运行模型摘要 API，保留角色边界并同步契约。
- [x] 完成前后端静态、单元测试与构建，交付人工验收。

## 验收标准
- 页面标题层级与任务列表一致；聊天不再限制最大 720px，高度跟随视口与任务概览变化。
- 输入框和“发送”同排、消息区独立滚动；不显示“等待业务说明”。
- 首次调用前显示运行模式和可用模型，调用后展示响应的实际模型、最近调用 Token 与耗时；无统计时使用未调用状态，不伪造总消耗。
- 模型摘要仅 OPERATOR/PLATFORM_ADMIN 可读，仅含 mode/modelName，无启用模型时 modelName 为 null。
- 测试、契约、类型检查和构建有真实结果；不启动或重启服务，不自动创建提交。

- 刷新前端，确认“业务处理”标题与任务列表标题层级一致。
