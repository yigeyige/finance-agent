## 需求

### ID&标题

- 业务处理向导升级（调查与调整）

### 描述

- 将现有“业务调查向导”调整为通用的“业务处理向导”，同时覆盖业务调查和业务调整。
- 第一步由管理员输入业务标题与业务说明，并用于任务总览列表。
- 将“确认对象”和“设置范围”合并为一个步骤，先由大模型基于业务说明提供对象与范围初稿，管理员再修订确认。
- 取消当前方案批准环节；管理员直接生成业务方案，并可在大模型对话框中反复沟通、修改方案后提交。

## 背景

- 现有流程围绕“调查”设计，拆分了对象确认、范围设置、方案建议和人工批准，管理员需要在多个页面区块间重复录入。
- 业务处理还可能是调整而非调查，术语与后续方案需要具备更通用的表达。
- 已有受控模型交互能力可以安全提供结构化初稿，但当前仅能在范围确认后生成调查步骤，无法支持前置引导与会话式修改。

## 目标

- [x] 将首屏术语、任务概览和向导步骤调整为业务处理语义，保留既有任务与调查能力兼容。
- [x] 合并对象确认与范围设置，模型在业务说明提交后生成可编辑的对象、范围和业务方案初稿。
- [x] 提供管理员可用的模型对话框，支持依据自然语言反馈重新生成或修改业务方案。
- [x] 移除页面上的人工批准方案步骤，管理员可直接提交方案并进入后续执行。
- [x] 补充受控模型接口、失败处理和前后端验证。

## 验收标准

- 首页第一步只要求业务标题和业务说明，创建后的任务仍在任务总览中可识别。
- 第二步单页展示并允许修改模型预填的业务对象、信息依据、系统、时间范围和处理内容。
- 管理员可以在模型对话框中输入修改意见，界面展示模型回复并更新业务方案建议。
- 页面不再要求选择批准/拒绝或填写审批次数；直接生成方案后进入现有后续处理链路。
- 模型输入仍由后端受控构造，不返回推理过程、原始提示词或未授权字段；前后端构建和相关测试通过。
