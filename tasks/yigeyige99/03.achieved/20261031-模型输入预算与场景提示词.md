## 需求

模型输入预算与审批流程场景提示词修正

### 描述

为「审批流程生成-隆地」调查提示词生成 Flyway 迁移，禁止查询 `basedata.t_org_process_template`；按用户确认的 `deepseek-v4.1-flash` 输入上下文 1M、输出上限 384K，将本地输入门禁调整为输入上限的一半。

## 背景

- 当前流程文件生成前用 UTF-8 字节数作保守输入规模检查；`deepseek-v4.1-flash` 未列入模型档位，落入默认 48,000 字节阈值，触发“本次模型输入超过可用上下文”。
- 运行中的场景调查提示词已通过管理接口加入禁查规则，但仓库尚无对应迁移；部署到其他环境时需要持久化。
- 用户确认该模型的输入上下文上限为 1M、输出上限为 384K；本次只调整本地输入门禁，输出配置不在本任务范围。

## 目标

- [x] `deepseek-v4.1-flash` 的本地输入门禁按 1M 的一半设置，其他模型规则不变。
- [x] 新迁移只给目标场景调查提示词追加禁查规则，不覆盖其它提示词内容。
- [x] 完成相关静态检查、编译和针对性测试；启动及人工验证由用户执行。

## 验收标准

1. 当前模型的 500,000 UTF-8 字节输入允许通过，超过该值被中文提示拒绝；未知模型及已有模型门禁保持现状。
2. 迁移 SQL 仅更新「审批流程生成-隆地」场景且幂等追加禁查语句；重复执行不重复追加，其他场景及决策包/生成提示词不变。
3. 不自动启动应用、不执行本地迁移；记录验证结果及未验证边界。
