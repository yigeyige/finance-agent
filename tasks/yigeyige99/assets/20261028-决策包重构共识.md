# 决策包重构共识（2026-10-28）

> 来源：基于《决策包现状分析》的 grill-me 评审结论。本文档为切片更新与实施的依据。

## 一、方向

- 走 B 的「独立模型分析」能力 + A（`businesspacket`）的存储，去掉状态机。
- B 的 `packet` 包与前端 `PacketDraft.vue` / `PublishedPacket.vue` / `EvidenceOverview.vue` **保留不动**。
- 生成决策包为**同步单请求**：固定输入 → 调模型 → 组装 content → 保存修订 → 返回。**不建快照表**。

## 二、切分（3 片）

1. `analyze-frozen-business-evidence`（后端·模型端口）
2. `finalize-business-packet-revisions`（后端·编排 + 持久化 + 锁定，**并入固定输入组装**）
3. `present-internal-business-packets`（前端）

取消原 `capture-business-evidence-lineage` 独立片，其「固定输入」内容并入第 2 片。

## 三、数据流与契约

```
模型返回（切片1，BusinessModelClient 新方法输出）
  subjectKey / conclusion / recommendedGoal / alternativeGoals / reason

        ↓ 切片2 generate 组装

后端 content（canonicalContent，返回给前端）
  packetId / taskId / revision / createdAt
  subjectKey / conclusion / recommendedGoal / alternativeGoals / reason
  sceneSkillId / sceneSkillName
  databaseConfigId / databaseInstanceName
  evidence
```

### 固定输入（模型输入）

- taskId + title + originalQuestion（从 `InvestigationTask` 读）
- 已有累积证据（从证据工作区读）
- `decisionPacketPrompt`（从任务关联场景 Skill 读；未选场景沿用通用提示，场景失效报错）
- title/originalQuestion 只用于模型分析，**不落进包 content**（展示时查 taskId）。

### 模型输出（切片1 定义）

- `subjectKey`（处理对象，由模型分析得出，不从任务前提/草稿读）
- `conclusion` / `recommendedGoal` / `alternativeGoals` / `reason`
- 不接受模型造证据，证据由服务端固定输入绑定。

### content（切片2 定义，切片3 展示）

- 不存 `title / originalQuestion`（查 taskId）。
- 去掉 `objectKey`、`statement`（前端残留）。
- `sceneSkillId/Name`、`databaseConfigId/Name` 存 id+name（留痕）。

## 四、锁定规则（切片2）

- 锁定范围 = `updateTask` 的三个字段：`originalQuestion / businessSceneSkillId / databaseConfigId`。
- 实现 = `updateTask` 加「该任务已有决策包则拒绝」校验。
- `title` 创建后本就不可改，无需锁；`subjectKey` 是模型结果非任务信息，不锁。
- 首次生成失败且无已有包时不锁定；补证和再次生成仍可用。

## 五、关键现状确认

- `TaskPremise` 半废弃：写入侧 `addPremise` 前端已无调用（死接口）；读取侧仅旧 `TaskDetail.vue` 引用。`subjectKey` 不再从 TaskPremise 读，改由决策包模型分析产出。
- 现有 `BusinessDecisionPacketService.generate` 纯组装（读草稿 + 去重证据），不调模型，将重构为「固定输入 → 调模型 → 组装 → 保存」。

## 六、遗留待办分支（未在本轮确认）

- 切片1 原设计「取消按 schema/table/purpose 去重」与「输入超限直接报错」的关系需在实施时定夺。

## 七、复核补充结论（2026-10-28）

1. **锁定校验放 web 层**：`TaskIntakeController.updateTask` 注入查询，用 `findLatestByTaskId(taskId).isPresent()` 判断「已有包」；避免 task ↔ businesspacket 模块循环依赖。并发靠 generate 保存的 `(taskId, revision)` 唯一约束防重复修订；「校验通过后、保存前」的极小并发窗口接受（管理员单人使用），不引入额外锁表。
2. **证据沿用去重**：固定输入的证据沿用现有 `deduplicate`（按 schema/table/purpose 去重 + ≤50），模型输入与 content 的 evidence 一致。
3. **模型输出新建精简 record**：新建 `BusinessPacketAnalysisSuggestion`（subjectKey/conclusion/recommendedGoal/alternativeGoals/reason 5 字段），不复用 `BusinessHandlingDraft`，最小化模型 token。
4. **未选场景/实例时 content 字段显示空**：sceneSkillId/Name、databaseConfigId/Name 为 null 时按空处理；「未选场景沿用通用提示」的具体来源待切片1实施时定。
5. **模型调用在保存事务外**：generate 拆成「非事务模型调用 + 事务保存」。
6. **前端 title/question 复用页面已加载信息**：不新增接口；WorkbenchHome 用 task.title + form.question，TaskDetail 用 detail.title + detail.description。
