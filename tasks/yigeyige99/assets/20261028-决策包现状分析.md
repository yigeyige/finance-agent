# 决策包现状分析（2026-10-28）

> 目的：梳理决策包当前实现，供后续讨论调整方向使用。本文档为只读分析，不含改动方案。

## 一、两套并存的决策包实现

决策包目前有**两套并存**的实现，职责有重叠。

### A. 业务决策包（一键生成，简单版）

- 入口：`WorkbenchHome.vue` 第二步「生成业务决策包」按钮
- 接口：`POST /api/v1/tasks/{taskId}/decision-packet`，另有 `GET /latest`、`GET /revisions/{n}`、`GET /evidence`
- 核心：`BusinessDecisionPacketService.generate`
  - 路径：`backend/src/main/java/cn/com/crc/ems/finance/agent/businesspacket/application/BusinessDecisionPacketService.java:64`
- **完全不调模型**：读取最新草稿 `BusinessHandlingDraft` + 证据工作区累积证据，按 `schema/table/purpose` 去重（≤50 条），组装后 `revision` 递增（内容不变则跳过）
- 规格：`openspec/specs/business-decision-packet/spec.md`（3 个 requirement：证据累积、生成、查看）
- 控制器：`businesspacket/web/BusinessDecisionPacketController.java`

### B. 结构化决策包（草稿→复核→发布，完整版）

- 入口：`EvidenceOverview.vue`（证据采集）→ `PacketDraft.vue` → `PublishedPacket.vue`
- 接口：`packet-drafts` → `reviews` → `packet-publications`（`frontend/src/services/packet-api.ts`）
- 流程：模型分析证据 → 生成草稿（纯前端组装）→ 复核 → 发布（不可变修订 + HTML 快照）
- 相关：`frontend/src/views/PacketDraft.vue`、`frontend/src/views/PublishedPacket.vue`

## 二、模型分析逻辑（关键）

真正调模型的地方只有**两处**，均在 `BusinessModelInteractionService`：

1. **业务处理初稿** `guideBusinessHandling`
   - 路径：`backend/src/main/java/cn/com/crc/ems/finance/agent/model/application/BusinessModelInteractionService.java:108`
   - 注入 `investigationPrompt`，产出 `BusinessHandlingDraft`（结论 / 推荐方案）
2. **证据分析** `analyzeEvidence`
   - 路径：`BusinessModelInteractionService.java:199`
   - 只分析脱敏证据摘要（生效计数 + 覆盖完整度 + finding 陈述），产出 `EvidenceAnalysisSuggestion`（summary / riskLevel / riskExplanation / recommendations）

由此带来三个现状：

- **简单版决策包（A）没有独立模型分析**：结论直接复用「业务处理初稿」的 `conclusion/recommendedGoal`。
- **完整版决策包（B）的模型分析**（`analyzeEvidence`）只用于页面 transient 展示风险和建议，**其结论没有进入最终的决策包草稿 / 发布内容**（`PacketDraftResponse` 里只有 canonicalJson / htmlSnapshot）。
- **`decisionPacketPrompt`（决策包提示词）目前悬空**：`findSceneSkill` 把它读进 `BusinessSceneSkillContext`（`BusinessModelInteractionService.java:180`），但没有任何一个决策包环节消费它——两套决策包都不在「生成决策包结论」时调模型。

## 三、决策包结构

### 简单版（A）领域结构

```text
BusinessDecisionPacket(packetId, taskId, revision, canonicalContent, contentDigest, createdAt)
```

- `canonicalContent` 是权威规范 JSON 文本，`contentDigest` 为内容摘要绑定不可篡改
- `content` = 草稿字段（subjectKey / objectKey / recommendedGoal / alternativeGoals / reason / conclusion）+ `evidence[]`
- 前端契约：`frontend/src/api/generated/index.ts:458`
  - `BusinessDecisionPacketContent = { packetId, taskId, revision, createdAt, conclusion, recommendedGoal, reason, statement, evidence[] }`

### 完整版（B）结构

```text
PacketDraftResponse（canonicalJson + htmlSnapshot + contentDigest + draftNo + scopeRevisionId + runtimeBundleId）
PacketReviewResponse（decision: APPROVE/REJECT + comment）
PacketPublicationResponse（published + recheckDecision + diffs）
```

## 四、界面展示

| 页面 | 展示内容 |
| --- | --- |
| `WorkbenchHome.vue` 第二步 | 简单版：conclusion / recommendedGoal / evidence |
| `PacketDraft.vue` | 完整版：模型分析证据（手动触发）→ 草稿复核 → 发布 |
| `PublishedPacket.vue` | 已发布决策包只读查看 |
| `EvidenceOverview.vue` | 证据采集（完整版入口） |

## 五、已发现问题 / 调整点

1. **`decisionPacketPrompt` 无消费方（悬空）**——最需要决策的方向：要不要让决策包生成时真正调用模型 + 注入决策包提示词。
2. **两套决策包并存、职责重叠**——「一键生成」和「草稿→复核→发布」都叫决策包，入口、结构、流程完全不同，需要明确哪套是最终形态，或如何归并。
3. **完整版模型分析结论未固化**——`analyzeEvidence` 的风险判断 / 建议只展示、不落进决策包内容，决策包产物缺少「模型分析」这一层。
4. **契约残留**：前端 `BusinessDecisionPacketContent` 还有 `statement` 字段（`generated/index.ts:458`），但草稿已删 `statement`，后端决策包内容里不会再出现该字段。
5. **简单版 content 字段缺失**：`alternativeGoals` 未被前端契约声明（前端只取 conclusion / recommendedGoal / reason / statement / evidence），备选方案在界面上会丢失。

## 六、待定方向

- 决策包是否要独立调模型 + 消费 `decisionPacketPrompt`（决定后续是增强简单版，还是把完整版的模型分析结果固化进产物）
- 两套决策包是保留其一，还是合并
