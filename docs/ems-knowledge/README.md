# EMS 财务系统知识库

本目录沉淀 `ems-财务系统-本地简易版` 的可复用结构知识，供后续业务场景分析、只读查询模板设计和人工处置建议使用。

## 当前边界

- 数据来源：DBX 连接 `ems-财务系统-本地简易版`。
- 查询方式：只读元数据查询和表结构查询，不写 EMS 数据库。
- 当前纳入快照：11 个业务或支撑库，共 905 张表；`information_schema.TABLE_ROWS` 均报告为 0，首轮关键表通过 `COUNT(*)` 复核也均为 0。
- 首版知识仅能确认库、表、字段、注释和数据库外键，不能证明实际数据分布、状态值使用情况或跨表业务关联；非关键表仍需按场景执行精确行数复核。
- 表中包含账号、人员、银行、发票、金额等敏感字段。后续查询必须按场景建立字段白名单，禁止为了探索而读取整行数据。

## 知识可信等级

| 等级 | 含义 | 使用要求 |
|---|---|---|
| `CONSTRAINT_VERIFIED` | 数据库存在主键或外键约束 | 可以作为确定性关系使用，但仍需考虑软删除和有效期 |
| `SCHEMA_VERIFIED` | 表、字段或注释已通过 DBX 核实 | 可以用于生成候选查询，业务语义仍可能需要确认 |
| `INFERRED` | 根据字段名、表名或同名编码推断 | 必须显式标记为推断，取得样本或代码证据后才能升级 |
| `PENDING_CONFIRMATION` | 状态码、权威来源或业务用法尚未确认 | 不得用于输出确认级业务结论 |

## 使用方式

1. 先从 [数据库总览](database-overview.md) 确定所属业务域。
2. 从 [关键表目录](key-table-catalog.md) 选择候选表和最小字段。
3. 查询外键约束；不存在外键时，再结合源代码、接口文档或脱敏样本验证候选关联。
4. 为具体业务场景建立固定、参数化、只读的查询模板，不允许模型临时拼接任意 SQL。
5. 查询结果必须保留来源库、表、主键、查询时点、知识版本和覆盖状态。

业务知识如何以受控检索、场景 Skill 绑定和查询模板接入业务处理 Agent，见 [EMS 业务知识接入 Agent 方案](../ems-knowledge-agent-integration-design.md)。

## 维护原则

- 知识记录稳定结构，不记录真实人员、账号、单据或金额。
- 备份表、临时表和日期后缀表默认不作为权威来源。
- 同一对象在多个库重复出现时，先标记来源冲突，不能凭表名自行选择。
- 每次补充知识时记录验证依据：数据库约束、表注释、字段注释、代码调用链、接口文档或脱敏样本。
- 不纳入 `claim`、`xxljob`、`arch_db`；这些库以业务单据、调度或归档数据为主，不属于本版业务配置知识域。
- 当前知识版本：`ems-local-schema-v1`，核查日期：2026-10-11。
