# EMS 业务知识接入 Agent 方案

## 1. 目标与边界

本方案将现有 EMS 业务知识域从“人工查看的结构目录”逐步升级为业务处理 Agent 可受控使用的知识能力，用于支持审批人员离职、流程参照创建、权限调整等财务运维场景的分析与人工处置建议。

目标：

- 在业务处理模型生成建议前，按场景检索最相关的 EMS 知识，而不是向模型注入完整知识库。
- 将业务场景 Skill、知识条目和只读查询模板联通，形成可解释、可审计的处理链路。
- 降低模型上下文与数据库结果带来的 token 消耗。
- 保持“只读、最小数据、人工确认后执行”的安全边界。

不在本方案范围内：

- 自动修改 EMS 流程、人员、权限或其他配置。
- 向模型暴露数据库连接信息、真实账号、完整单据、金额明细或未脱敏个人信息。
- 将 `claim`、`xxljob`、`arch_db` 纳入本版配置知识域。

## 2. 当前状态

当前能力由三部分组成，但尚未形成知识驱动闭环：

```text
任务 + 已选择的场景 Skill ──> 数据库查询规划 ──> 受限 SELECT 查询 ──> 查询证据
           └────────────────────────────────────────────> 业务处理模型

EMS 业务知识域 ──> 页面/API 展示
                    （未进入模型调用链）
```

| 能力 | 当前状态 | 限制 |
| --- | --- | --- |
| EMS 业务知识域 | 内置目录，展示业务域、库、关键表、可信边界和核验提示 | 不进入 `BusinessGuidanceContext`，不参与模型提示或查询规划 |
| 场景 Skill | 创建任务时由用户选择并固化，名称、说明、处理方式、前提类型会进入模型输入 | 未绑定 EMS 业务域、知识条目、查询模板或核验步骤 |
| 数据库辅助 | 模型先规划 SQL，服务端再通过只读 SQL Guard 校验并执行 | 只限制到库级白名单，模型仍可能虚构表、字段和关联；结果原样进入模型上下文 |

当前模型输入还可能同时包含长任务描述、附件原文与查询结果；虽有单项长度限制，但没有跨来源的统一 token 预算和优先级策略。

## 3. 设计原则

1. **先检索、后生成**：模型仅接收命中的知识摘要，不接收完整目录。
2. **知识与事实分离**：知识是表结构、流程规则和处置方法；实时查询结果只是待核验辅助证据，不能自动成为已确认事实。
3. **Skill 决定路径，知识提供依据**：Skill 定义场景的处理框架；知识条目为该框架提供候选对象、核验项和模板。
4. **模板优先于自由 SQL**：模型选择受控查询模板并填写参数，服务端决定实际 SQL。
5. **最小数据与可追溯**：只传必要字段、聚合结果和脱敏摘要；记录所用知识版本、Skill 版本、模板版本与查询时点。
6. **确定性优先**：现有知识规模和结构化程度适合先采用标签、关键词和绑定关系检索；不以引入向量库作为前置条件。

## 4. 目标架构

```text
任务描述 / 已选场景 Skill
             │
             ▼
        场景路由器
             │
             ▼
       知识检索服务
       ├─ 场景作业卡
       ├─ 表字段目录
       ├─ 核验步骤
       └─ 查询模板候选
             │
             ▼
       上下文预算编排器
             │
             ├─> 模板选择与参数提取 ─> 受控查询执行器 ─> 证据摘要器
             │
             ▼
        业务处理模型
             │
             ▼
 可编辑业务处理初稿 + 待确认事项 + 证据引用
```

### 4.1 知识条目模型

每条可供 Agent 使用的知识应成为独立、可版本化条目，而不是将整份 Markdown 或整个业务域直接投喂给模型。

建议字段：

| 分类 | 字段 |
| --- | --- |
| 身份与版本 | `knowledgeId`、名称、版本、状态、有效期、维护人 |
| 路由 | 业务域、场景标签、关键词、可绑定 Skill、优先级 |
| 内容 | 适用条件、候选对象、处理步骤、待确认事项、风险与禁止项 |
| 数据结构 | 受控库表、字段白名单、关系说明、可信等级 |
| 证据 | 验证依据、来源类型、最后核验时间、已知边界 |
| 工具 | 可用查询模板标识、参数定义、最大结果规模 |

知识内容应分层维护：

- **路由摘要**：领域、触发词、意图，用于低成本筛选。
- **场景作业卡**：业务步骤、人工确认点、建议输出结构。
- **结构知识**：库、表、字段、关系与可信等级。
- **查询模板**：固定参数化 SQL、字段与行数限制，仅在服务端保存和执行。

### 4.2 场景 Skill 扩展

保留现有场景 Skill 的任务级固定关联，扩展以下受控配置：

- 绑定的 EMS 业务域和知识条目；
- 必填对象类型，例如人员、工号、组织、流程编码、业务类别；
- 排查顺序与必核验项；
- 可使用的查询模板；
- 缺少必要信息时的追问规则；
- 输出结构、风险提示和人工审批要求。

场景路由优先级：

1. 用户在任务创建时显式选择的有效 Skill；
2. 基于关键词、业务域和对象类型的候选 Skill 推荐；
3. 未命中时使用通用“待澄清”路径，不自动猜选或变更任务已固化的 Skill。

### 4.3 查询模板执行

将“模型产出任意 SQL，Guard 再拦截”逐步收敛为：

```json
{
  "queryTemplateId": "APPROVER_ASSIGNMENT_BY_USER",
  "parameters": {
    "userId": "受控对象标识"
  }
}
```

服务端根据模板标识执行固定的参数化 SQL，并校验：

- 当前 Skill 是否允许该模板；
- 参数是否完整、类型是否正确、是否符合最小查询范围；
- 模板使用的库、表、字段是否处于知识白名单；
- 最大行数、超时、字段脱敏和结果摘要策略是否生效。

现有只读 SQL Guard 继续保留为纵深防御，但不再承担业务正确性和表字段真实性校验。

## 5. Token 预算方案

### 5.1 上下文分配

为一次业务处理调用建立统一的输入预算。预算数值应作为运行配置并通过实际评测调整，不在代码中散落固定字符长度。

推荐优先级：

1. 任务目标、当前草稿和用户反馈；
2. 已选场景 Skill 的结构化约束；
3. Top 3 至 5 条命中知识的紧凑摘要；
4. 查询结果的聚合/命中摘要；
5. 附件摘要或有限片段。

当预算不足时，按上述优先级截断，并在模型输入中标记“内容已裁剪、需要人工展开”，避免模型将缺失信息误判为不存在。

### 5.2 降本措施

- 不重复注入：查询规划只接收模板目录和参数规则；业务处理模型只接收已命中的作业卡和证据摘要。
- 结构化摘要：用知识 ID、模板 ID、表名、字段名、可信等级等短字段替代重复自然语言。
- 服务端结果归约：优先传递命中数量、配置类型、状态分布、主键引用和脱敏摘要，不传整行原始数据。
- 结果缓存：以“知识版本 + Skill 版本 + 场景意图 + 非敏感参数摘要”为键缓存检索结果；修订草稿时复用。
- 按需扩展：首次生成仅用摘要；用户请求“查看依据”或模型明确无法判断时，才检索下一层知识或补充查询。

### 5.3 观测指标

上线后应记录不含敏感正文的度量：

- 每类场景的输入/输出 token 区间；
- 知识命中率、Skill 绑定覆盖率、模板命中率；
- 查询拒绝率、空结果率和人工纠正率；
- 生成建议中“待确认项”与最终人工处置的一致性；
- 单次处理的模型调用次数与耗时。

## 6. 典型场景示例

### 6.1 审批人员离职

1. 用户选择“人员离职配置排查”Skill，并输入工号、姓名或用户标识。
2. 检索服务命中基础主数据、审批流程、付款权限等知识条目。
3. 模板选择器先执行“用户/员工/工号映射”模板，再按命中身份选择审批人、角色、付款权限等模板。
4. 证据摘要返回“命中配置类型、候选表、记录数量、待确认字段”，不将查询结果直接视为要变更的对象。
5. 模型输出排查清单、影响范围、建议替代规则和必须人工确认的事项；实际变更仍由人工审批与执行。

### 6.2 参照出差申请生成采购申请审批流程

1. 用户选择“审批流程参照设计”Skill，提供参考流程和目标流程的编码或名称。
2. 检索审批流程作业卡，获得流程集、版本、节点、连线、处理人、表单绑定等核验顺序。
3. 仅使用“流程结构对比”模板读取受控配置结构。
4. 模型输出采购流程草案及差异清单，并把金额阈值、组织范围、处理人规则、表单字段映射标为待确认。
5. 不自动复制、发布或启用流程；由流程管理员在 EMS 中完成受控配置和验证。

## 7. 实施阶段

### 阶段 A：确定性联通

- 将现有 EMS 业务域目录拆分为可检索知识条目，并保留现有展示页面。
- 为场景 Skill 增加知识条目与业务域绑定。
- 在业务处理上下文中注入命中的紧凑知识摘要、版本和可信边界。
- 引入统一上下文预算器与结果摘要器。

验收重点：已选 Skill 能命中并引用对应知识；未命中时明确提示待澄清；模型不接收完整知识目录。

### 阶段 B：模板化查询

- 建立查询模板、参数模式、字段白名单和 Skill 授权关系。
- 将数据库辅助从自由 SQL 规划迁移为模板选择与参数提取。
- 补充模板测试、拒绝路径测试和查询审计。

验收重点：模型无法指定未授权表字段或任意 SQL；所有实际查询可追溯到模板和知识版本。

### 阶段 C：知识运营与评测

- 增加知识草稿、复核、发布、失效和版本回滚流程。
- 建立典型场景评测集，覆盖人员离职、流程设计、角色权限、付款权限等。
- 根据知识规模评估是否引入“关键词 + 向量”的混合检索；向量检索只能作为召回手段，仍由可信等级、Skill 绑定和权限过滤进行最终筛选。

## 8. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 表结构被误解为业务规则 | 所有条目标明可信等级和验证依据；推断知识不得输出确认级结论 |
| 模型虚构表、字段或 SQL | 模板化查询、表字段白名单、服务端参数校验和保留 SQL Guard |
| token 随附件和结果暴涨 | 检索 Top-K、统一预算、服务端摘要、按需展开 |
| Skill 修改影响历史任务 | 任务保存 Skill/知识/模板版本快照，历史建议按快照解释 |
| 查询结果含敏感信息 | 字段最小化、脱敏、行数限制、结果不写入模型审计日志 |
| 知识过期 | 版本、有效期、最后核验时间、到期提醒和人工复核流程 |

## 9. 推荐的下一步

优先启动“EMS 知识检索与场景 Skill 联通”能力切片，范围限定在阶段 A：将已存在的 EMS 知识目录转换为受控、可检索的上下文摘要，并与现有任务级场景 Skill 建立绑定。完成后再独立实施查询模板化，避免在同一变更中同时改动知识、模型编排和数据库执行边界。
