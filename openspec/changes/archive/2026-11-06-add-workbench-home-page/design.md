## Context

当前前端只有工作台页面：`/` 直接渲染 `WorkbenchHome.vue`，登录成功后 `replace('/')`，左侧菜单第一个入口也指向 `/`。页面之间通过 `/tasks/:taskId/...` 子页跳转，子页的“返回任务”按钮也硬编码 `push('/')`，依赖工作台被 `keep-alive` 缓存来保留当前任务状态。

## Goals / Non-Goals

**Goals:** 登录后进入一个纯介绍型首页；业务处理保留原有 `keep-alive` 会话状态和草稿重置语义；旧根路径不会停留在无意义页面；导航与返回路径显式、可测试。

**Non-Goals:** 不新增后端接口、数据库迁移或依赖；不在首页展示任务统计或 token 用量；不改变业务处理内部三步流程与权限模型。

## Decisions

- **路由布局**：`/home` 为首页，`/handling` 承载 `WorkbenchHome`（保留组件名 `WorkbenchHome` 以继续命中 `keep-alive`），`/` 仅做重定向到 `/home` 并丢弃 query。
- **身份守卫**：两个新路由显式声明 `requiresIdentity`，守卫条件从“`to.path === '/'`”改为读取该标记，避免未登录用户直接渲染受保护页面。
- **菜单与顶栏**：菜单第一个入口为“首页”（不做权限限制）；“业务处理”仍要求 `TASK_READ`；首页由 hero 承担标题层级，`App.vue` 在 `home` 路由隐藏顶栏 `h1`，右上角身份菜单保持不变。
- **草稿语义**：首页快捷卡、左侧菜单和任务列表的新建入口都跳转 `/handling?draft=<ts>`，沿用既有 `resetDraft()` 逻辑；子页“返回任务”不带 `draft`，保持当前处理进度。
- **首页内容**：只使用静态文案与 CSS 绘制的几何装饰，不引入图片或图表库；版式为 hero 通栏 + 业务处理快捷卡 + 三步指南，后续 token 卡片再改为左右分栏。

## Risks / Trade-offs

- 旧书签 `/` 会被带到首页而非业务处理页：内部入口已全部更新，外部长期书签需用户重新收藏。
- 菜单新增“首页”后，`PLATFORM_USER` 的可见菜单从 4 个变为 5 个，需同步身份导航规范。
- 隐藏首页顶栏 `h1` 后，首页标题层级完全依赖 hero，后续新增页面不得复用该隐藏逻辑。
