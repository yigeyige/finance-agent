## Context

任务列表仓储当前使用 `selectPage(new Page<>(...))`。项目只配置 Mapper 扫描和 UUID 类型处理器，未注册 MyBatis-Plus 分页拦截器；因此页面参数没有进入 SQL，`total` 保持零。当前请求边界规定页码至少一、每页最多一百条。

## Goals / Non-Goals

**Goals:** 让身份、状态、标题筛选下的总数准确，记录读取在数据库端按页限制，并保持稳定排序。

**Non-Goals:** 不修改前端分页组件、响应字段、数据库结构或其他仓储查询。

## Decisions

- 复用现有 MyBatis Mapper，添加同一筛选条件的 `COUNT(*)` 和 `LIMIT/OFFSET` 查询，所有值通过 `#{}` 绑定。相比新增解析器依赖和全局拦截器，这个修复只影响任务列表，也符合项目新增依赖需单独确认的规则。
- Mapper 使用同一静态筛选 SQL 片段构建两条注解查询，避免两处条件漂移；可选发起人、状态及标题条件由 MyBatis 动态标签控制。
- 仓储验证页码与条数，使用长整型计算偏移量；先读取总数，再读取当前有界页。零条时返回空列表。

## Risks / Trade-offs

- 总数和记录是两条只读语句，期间有新增任务时可能发生短暂并发变化；当前接口无快照一致性承诺，且两条查询使用相同筛选条件。
- 本轮按用户规则不启动本地服务，实际 HTTP 与 PostgreSQL 数据验收由用户完成。
