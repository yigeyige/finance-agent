## Context

当前 `GlobalApiExceptionHandler` 处理未预期 API 异常；业务模型通过统一 `BusinessModelClient` 端口调用，部分模型辅助失败在客户端内部恢复，最终失败则穿出端口。服务单实例，管理员只需查看最近一次堆栈。

## Goals / Non-Goals

**Goals:** 只保留一条线程安全、不可变、受限大小的异常快照；捕获未预期 API 失败与所有最终失败的模型端口异常；仅平台管理员按需读取。

**Non-Goals:** 不持久化、不自动刷新、不收集已经内部恢复的模型异常、不修改现有异常响应语义。

## Decisions

- 使用 Spring 单例组件中的 `AtomicReference` 保存最近快照，包含 UTC 时间、来源类别、异常类名和堆栈帧。写入时格式化，不保存 `Throwable` 或原始请求、提示词、响应、SQL、异常消息；根因只保留类型和帧，限制层数、帧数与总长度。避免依赖不可靠的任意原文过滤来阻止敏感数据泄露。
- 在统一异常处理器的未知异常出口写入业务失败；在模型端口外围使用显式装饰器记录向调用方抛出的任意 `RuntimeException`，覆盖各模型用例及供应商适配器，内部恢复的异常不穿出端口。
- 新增只读 API，控制器和权限拦截器均校验 `PLATFORM_ADMIN`。前端沿用工作台卡片、菜单和路由，页面创建时请求一次，显示空状态或错误。

## Risks / Trade-offs

- 同时发生的异常仅保留最后一次 → 符合单实例最近一条需求；不提供历史和清除操作。
- 任意原始异常消息可能包含敏感值 → 页面只展示异常类型与堆栈位置，避免原始消息、请求数据进入快照。
- 服务重启后快照丢失 → 页面展示无异常空状态，符合无持久化约定。
