## Context

P0 已提供完全离线、固定 seed 的 `SyntheticConfigSourceAdapter`。它登记了 `source-catalog-v1`、查询模板 `config.employee.references.v1` 和 `page` / `size` 参数白名单，输出仅含 `syntheticEmployeeId`、`syntheticReferenceId` 与 `classification` 的虚构记录。P1 原基线却以真实源、真实字段权限、真实凭证和外部签署作为入口，和当前测试业务验证目标不匹配。

本次参与方是功能运维、测试执行者和项目维护者。约束是：不读取或连接生产数据源；不保存真实人员、金额、单据、凭证或生产配置；不改变当前应用的运行路径。生产真实源接入仍由 P2 外部事实门禁控制。

## Goals / Non-Goals

**Goals:**

- 将 P1 的试点输入限定为可重复的测试业务源和虚构/脱敏样本。
- 复用当前合成适配器的固定 SourceCatalog 和注册模板，形成可审阅的目录、字段权限、样本和错误语义交付物。
- 保留 `UNKNOWN` 与 `CONFLICT`，使未知和冲突不会被测试样本或模型伪装成确认事实。
- 在基线、任务与 OpenSpec 中明确 P1 测试完成不等于获得生产接入授权。

**Non-Goals:**

- 不新增真实源适配器、网络连接、凭证、环境变量或数据库迁移。
- 不把虚构标识映射为真实人员，不建立生产认证或 break-glass 流程。
- 不修改 P2 的真实源、正式认证、生产数据边界和放行门禁。

## Decisions

### 1. 将现有合成配置源作为唯一测试业务源

测试目录固定使用 `source-catalog-v1` 和 `config.employee.references.v1`，不新建并行的测试数据提供者。这样能让目录文件、接口契约和已有纵向切片使用同一模板、版本和分页边界。

备选方案是新建独立 mock 服务。它会重复 adapter 的语义并引入网络、可用性和数据漂移变量，因此不采用。

### 2. 将“签署”替换为仓库内的测试边界确认

P1 测试目录由任务交付物、OpenSpec 验收和项目维护者确认组成；每个字段的读取、留存和送模权限都必须明确为允许、禁止或未知。该确认只对固定测试源生效，不构成真实数据、生产凭证或生产接入的批准。

备选方案是沿用真实数据源负责人签署。该做法会错误地要求当前测试业务提供生产级外部材料，因此不采用。

### 3. 按最小字段和注册参数冻结契约

测试记录只允许三个已存在的合成字段；`syntheticEmployeeId` 和 `syntheticReferenceId` 仅用于测试范围匹配、不得送模或作为真实身份，`classification` 可进入规则判断。查询只接受 `page`、`size`，且页号和大小的边界沿用适配器的正整数和 `size <= 100` 规则。

备选方案是文档中预先列出未来真实对象和物理字段。那会制造未经证实的字段契约，故保留到 P2。

### 4. 用场景矩阵表达覆盖与失败关闭

目录交付物列出基线、无匹配、分页失败、冲突、未来、未知和新增引用等固定场景，明确其预期分类或失败结果。测试源不可用、目录版本不匹配或模板/参数未登记时必须拒绝，不能改连真实源或返回空成功。

## Risks / Trade-offs

- [测试样本覆盖不足以代表生产复杂度] → 基线和交付物明确它只验证契约与流程；生产准确率、容量和真实字段语义仍由 P2 重新验收。
- [测试标识被误当作真实身份] → 字段矩阵标记为虚构标识，禁止映射、外送和日志扩散。
- [未来真实源接入绕过测试边界] → `source-adapter-spi` 要求生产占位保持失败关闭，且真实源继续受 P2 外部事实阻断。
- [文档与代码漂移] → 目录直接引用当前 adapter 中的版本、模板、参数和场景；本任务的静态检查会核对这些固定标识。

## Migration Plan

1. 更新 P1 入口、依赖阻断和总览措辞为测试业务源。
2. 交付 SourceCatalog、字段策略、查询与样本矩阵，并在 `DEV-P1-002` 中记录确认范围。
3. 不发布、不迁移、不变更运行配置；如需回退，只恢复上述 Markdown 交付物和基线文字。
4. 日后启动真实源工作时，另建 P2 change，重新收集真实字段、凭证、授权、故障和数据边界证据，不能复用本任务的测试确认作为批准。

## Open Questions

- 无阻塞问题。真实源的对象、字段、责任人和授权仍维持 P2 外部事实，待相应生产接入任务再确认。
