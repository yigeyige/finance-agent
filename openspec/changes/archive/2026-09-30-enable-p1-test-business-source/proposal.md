# 以测试业务源开展 P1 试点

## Why

P1 的原始基线要求接入真实源、真实字段权限和测试环境凭证，当前并不需要、也不应处理生产或真实业务数据。继续以这些外部事实作为 P1-ENTRY 会阻塞已具备的本地测试能力，且容易让测试验证与生产接入边界混淆。

本变更将 P1 试点明确限定为测试业务源：只使用固定、离线、虚构或已脱敏的样本，先冻结可重复验证的 SourceCatalog、字段权限和查询语义。生产真实源仍保留为 P2 前的独立外部事实门禁，本变更不授权生产连接、凭证、真实数据或生产部署。

## What Changes

- 将 P1 基线从“真实源试点”调整为“测试业务源试点”，重写 P1-ENTRY 为本地/测试环境可验证的门禁。
- 以现有 `SyntheticConfigSourceAdapter` 的固定目录、模板和场景为唯一 P1 测试业务源，冻结测试 SourceCatalog、字段三类权限矩阵、查询模板及有效/无效样例。
- 保持未知和冲突样本的 `UNKNOWN` / `CONFLICT` 语义，明确不以模型或未登记规则替代。
- 规定 P1 试点不得读取、留存、送模或输出真实人员、金额、单据、凭证或生产配置；不得在测试源不可用时回退连接真实源。
- 将真实源适配、真实凭证、真实字段授权和生产统一认证调整为 P2 的独立外部事实，不因 P1 测试完成而自动解除。

## Capabilities

### New Capabilities

- `test-business-source-contract`：定义 P1 测试业务源的目录、字段权限、样本、查询和数据边界契约。

### Modified Capabilities

- `source-adapter-spi`：补充测试业务源与生产真实源的隔离和失败关闭要求。
