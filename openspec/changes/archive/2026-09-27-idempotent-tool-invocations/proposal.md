## Why

工具调用目前只有持久化模型和唯一约束，应用层尚未把“写调用意图、执行、完成或结果未知”的生命周期统一起来。Worker 重启、重复 HTTP 请求或网络超时可能让调用方无法安全判断是否已经产生副作用，因此需要把幂等键、状态转换和重放规则固化到可测试的服务边界。

## What Changes

- 增加由 `taskId + stepId + approvalRevision + invocationNo` 组成的规范化工具调用幂等键。
- 增加幂等服务：工具执行前原子记录调用意图，重复请求读取既有记录，已完成结果可重放。
- 增加受约束的调用状态机，区分明确失败与结果未知；未知状态只返回人工核对，不使用同一幂等键盲目重试。
- 增加并发插入和状态转换的冲突处理，确保 HTTP 重复请求与 Worker 重启不会创建第二条执行意图。
- 保存请求摘要、响应摘要、错误码和审计时间，保留完整调用记录供恢复与审计使用。

## Impact

- 后端任务运行时新增调用键值对象、幂等应用服务及状态转换接口。
- MyBatis-Plus 工具调用仓储增加带期望状态的条件更新，复用现有 `task.tool_invocation` 表及唯一约束，不引入新的外部依赖或数据库迁移。
- 新增单元/契约测试覆盖成功重放、未知状态、并发重复插入和非法状态转换。
