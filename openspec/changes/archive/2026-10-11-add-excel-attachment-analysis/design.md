## Context

当前附件解析器仅严格解码 UTF-8 文本并将其限制为 24,000 个模型字符。`.xls`、`.xlsx` 都不能直接交给当前仅发送文本消息的模型客户端；业务材料必须先被后端提取为临时、可审计边界内的文本投影。用户已明确授权引入 FastExcel。

## Goals / Non-Goals

**Goals:**

- 使用 `cn.idev.excel:fastexcel:1.3.0` 的流式读取能力支持 `.xls`、`.xlsx`。
- 让模型看见工作表名称、表头和行值，同时保持现有 24,000 字符总预算。
- 在库读取前后限制文件、工作表、行、列与单元格文本，解析异常时不调用模型。

**Non-Goals:**

- 不支持 `.xls`、`.xlsm`、CSV 以外的办公文档、图片、公式计算结果校验或单元格样式。
- 不保存工作簿、解析文本、表头或模型提示词，也不改变人工确认边界。
- 不让模型直接读取文件二进制、执行公式、宏或下载外部链接。

## Decisions

### 1. 使用 FastExcel 1.3.0 解析 `.xls`、`.xlsx`

FastExcel 1.3.0 的 `cn.idev.excel:fastexcel` 依赖兼容 Java 17，并提供面向大文件的流式读写 API。解析器只使用读取 API，逐行生成文本投影；不引入独立的 POI 调用或工作簿持久化。

备选方案是把二进制工作簿直接交给模型供应商。当前模型适配器只发送文本，且该方案会跳过可控的内容和保留边界，故不采用。

### 2. 多层结构配额与全局文本配额

每个 Excel 附件最多解析 5 个工作表、每表 200 行、每行 50 列、每个单元格 500 字符。任何结构上限超出即拒绝，不静默遗漏；生成的表格文本仍通过现有全部附件共享的 24,000 字符预算截断。每份 Excel 投影标明是否因文本预算被截断。

### 3. 只投影显示文本和位置

输出使用“工作表—行—列—值”的文本格式，不携带样式、批注、图片、公式定义、宏或隐藏数据。FastExcel 抛出的读取、加密或 ZIP 格式异常统一收敛为中文附件解析失败，不包含路径、工作簿正文或依赖库异常详情。

## Risks / Trade-offs

- [压缩炸弹或巨大工作簿] → 保持 1 MB 上传限制，并在流式回调中按工作表、行、列和文本边界停止。
- [公式、日期和空单元格显示与 Excel 不同] → 仅取库提供的值文本，向模型标注为待核验材料，不将其写入权威状态。
- [FastExcel 引入 POI 传递依赖] → 使用固定版本，运行 Maven 依赖与编译测试确认无现有冲突。
- [用户需要 `.xls` 或宏表] → 返回明确格式限制，另行评估安全解析和数据保留方案。

## Migration Plan

1. 增加 FastExcel 依赖及后端解析分支，保留原文本附件路径。
2. 前端文件选择白名单加入 `.xlsx`；已有客户端仍可发送无附件或文本附件。
3. 回滚时移除 Excel 分支和依赖；既有附件接口与任务数据不受影响。

## Open Questions

- 若后续需要大于 1 MB 或含大量工作表的工作簿，应单独确认文件扫描、队列化解析、数据分级和模型上下文预算。
