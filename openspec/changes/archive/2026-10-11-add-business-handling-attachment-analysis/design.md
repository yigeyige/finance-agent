## Context

业务处理初稿接口当前只从已创建任务读取标题、业务说明和已关联的业务场景 Skill。浏览器不应自行将附件内容拼接到模型提示词，真实模型客户端也只发送后端构造的文本消息。项目未配置通用文档解析依赖，且本次不需要持久化附件或让附件进入任务权威数据。

## Goals / Non-Goals

**Goals:**

- 允许用户在创建任务后、请求模型初稿前附带少量 UTF-8 文本材料。
- 将格式、数量、空文件、文件大小和可送入模型的文本总量限制在后端，并向模型标注材料的非权威属性。
- 保持无附件和聊天修订的既有 JSON 契约、模型元数据和人工确认流程。

**Non-Goals:**

- 不解析 PDF、Word、图片、压缩包或办公文档，不新增内容解析依赖。
- 不保存附件、提取文本、文件摘要或模型提示词，也不让附件直接改变任务、范围或方案。
- 不将附件内容显示在响应、技术明细、审计事件或日志中；不在聊天修订阶段重复上传附件。

## Decisions

### 1. 采用初稿专用 multipart 接口，保留既有 JSON 接口

前端仅在已选择附件时调用 `POST /guidance/attachments` 并用 `files` 字段提交 multipart；无附件继续调用原 `POST /guidance`。这样不破坏既有客户端、JSON 契约或聊天修订接口，也让服务端能明确区分附件分析和普通初稿请求。

备选方案是把附件内容先转成 JSON 再提交。该方案会绕开服务端文件校验并允许浏览器任意伪造上下文，故不采用。

### 2. 后端将文件转换为临时受限文本投影

新增应用层附件解析器，允许 `.txt`、`.md`、`.csv`、`.json`，最多 3 个、单文件最多 1 MB，拒绝空文件、重复扩展名以外的格式和非 UTF-8 内容。解析器返回文件名和受限文本；服务在调用模型前将每份文本截断并将合计限制为 24,000 个字符。内容只在请求内存中存在，不写入数据库或对象存储。

备选方案是复用对象存储或新增数据库附件表。该方案能支持后续复用，但会扩大保留期限、权限与清理责任；本需求只要求创建时分析，因此不采用。

### 3. 附件作为显式非权威模型上下文

`BusinessGuidanceContext` 增加附件文本投影，`DeepSeekBusinessModelClient` 将其放在受控输入 JSON 中并要求模型仅将其作为“待核验的用户提供材料”。模型输出仍沿用严格草稿结构；任务前提、范围和步骤只能由管理员后续显式确认。

### 4. 前端使用现有 Element UI 上传组件管理本地文件

向导第一步使用 `el-upload` 的手动上传模式维护局部文件列表，展示文件名并允许移除。提交时禁用重复操作、失败时保留文件和用户填写的内容；不在浏览器读取或展示附件正文。

## Risks / Trade-offs

- [文本材料超出模型预算] → 服务端逐文件和总量截断，拒绝超出原始文件大小限制的上传。
- [附件携带不可信指令或敏感内容] → 模型提示词标明材料不具权威性，仍使用严格 JSON 输出且不记录正文；业务人员需确认草稿。
- [用户需要办公文档或图片] → 本次明确返回受支持格式提示，后续以独立变更评估解析库、恶意文件扫描、存储和数据保留策略。
- [multipart 解析错误] → 控制器映射为业务可理解错误，不调用模型，不写入任何附件内容。

## Migration Plan

1. 部署兼容的后端附件初稿接口和前端手动上传入口。
2. 无附件调用继续走原接口，因此可与旧前端兼容。
3. 回滚时移除前端入口；原 JSON 初稿和已创建任务不受影响。

## Open Questions

- 如后续需要支持 PDF、Office 或图片，应先确认允许的文件类型、解析与病毒扫描方案、数据分类、保存期限以及模型供应商文件能力。
