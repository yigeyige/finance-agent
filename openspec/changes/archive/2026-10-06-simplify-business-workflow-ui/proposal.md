## Why

当前工作台把 JSON、UUID、摘要哈希和内部版本字段直接交给业务人员填写，既难以理解，也容易因格式错误阻断本应由系统完成的调查流程。需要把接口级技术参数收回系统内部，让页面围绕业务问题、调查范围、复核判断和发布确认组织。

## What Changes

- 将任务发起改为清晰的业务步骤，使用对象、日期、调查内容和数据使用范围等普通表单自动生成范围结构。
- 将调查方案与审批卡改为选择和确认操作，自动生成目标摘要、来源绑定和策略版本。
- 决策包草稿根据当前任务证据自动组装，业务人员只填写问题说明并确认业务影响。
- 发布前重查数据由证据快照自动生成，不再要求手工输入来源版本、覆盖摘要或 JSON 数组。
- 原始 JSON 和内部摘要移入默认收起的技术明细，业务主视图使用中文摘要和状态。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `task-intake-scope-ui`: 范围确认使用业务表单并由前端构造严格请求结构。
- `plan-approval-progress-ui`: 方案和审批不再要求业务人员填写摘要、UUID 或内部版本。
- `packet-draft-assembly-ui`: 草稿基于现有证据自动组装，原始 JSON 仅作为只读技术明细。
- `packet-publication-recheck-ui`: 发布前重查数据由系统准备，页面只保留业务发布确认。

## Impact

- 主要修改 Vue 2 工作台、决策包页面、前端服务与公共样式。
- 复用现有后端 API 和证据接口，不改变数据库、权限边界或发布事务。
- 不引入新依赖；继续使用 Element UI 2.0.0 和现有 API 客户端。
