## Context

当前 Vue 工作台直接映射后端请求 DTO，因此范围确认、步骤审批、决策包组装和发布页面暴露了 JSON、UUID、哈希和内部版本。目标用户是财务运维业务人员，他们需要表达业务对象、调查边界和判断，而不是拼装接口负载。现有后端已经具备严格校验、证据查询和发布事务，本次可在前端增加业务视图模型与确定性转换完成优化。

## Goals / Non-Goals

**Goals:**

- 用四段式业务向导解释当前阶段、所需信息和下一步。
- 用普通输入、选择、日期范围和复选项生成范围与审批请求。
- 从证据接口生成决策包章节和发布重查快照。
- 将 JSON、摘要和内部标识放入默认收起的技术明细。

**Non-Goals:**

- 不改变后端状态机、权限、审计、幂等或发布事务。
- 不新增数据库字段、第三方依赖或生产数据源配置。
- 不把自动生成理解为绕过业务影响确认或复核。

## Decisions

### 1. 在前端服务层集中完成业务表单到严格契约的转换

页面维护易理解的业务字段，转换函数生成现有 API 所需的对象、数组、摘要和版本。相比放宽后端契约，这能保留服务端的严格校验和安全失败行为，也避免重复维护新旧接口。

### 2. 调查方案使用可编辑的系统建议，审批只展示业务边界

系统根据任务与范围生成推荐步骤，业务人员可以调整步骤文字和调用上限。目标摘要使用浏览器 Web Crypto 自动计算，来源绑定使用本次任务内生成的 UUID，策略和模板版本采用当前前端基线，不显示为输入项。

### 3. 决策包从脱敏证据视图确定性组装

快照按生效分类进入当前、未来和未确定事实；来源、计算见证、专业确认、建议与覆盖摘要均由证据响应映射。业务人员必须显式确认“已核对业务影响”后才能生成草稿。

### 4. 发布重查复用当前证据生成基线与当前快照

草稿组装时保存批准基线；发布时重新读取证据形成当前快照，再调用既有发布 API。这样业务页面无需输入 JSON，同时仍由后端执行确定性差异比较和原子发布。

### 5. 主视图使用业务摘要，技术明细默认收起

页面优先展示事实数量、覆盖状态、判断结论和下一步。原始 canonical JSON、摘要和内部版本保留在“技术明细”折叠区，满足排障与审计需要而不干扰业务操作。

## Risks / Trade-offs

- [风险] 自动映射遗漏证据字段导致草稿不完整 → 使用纯函数集中转换并覆盖空数据、三类事实和发布快照测试。
- [风险] 发布期间证据变化 → 发布前重新读取证据，继续由后端重查服务阻断差异。
- [风险] P0 合成环境仍依赖固定运行版本基线 → 固定值集中在服务常量，不在表单暴露；后续真实源接入时由配置接口替换。
- [风险] 页面状态更丰富后代码膨胀 → 将转换逻辑抽到独立服务，页面只负责编排和可见状态。
