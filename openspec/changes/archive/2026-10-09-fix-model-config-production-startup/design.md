## Context

真实模型连接在调用时从 `governance.model_connection_config` 读取，数据库中的 API Key 由部署级主密钥加密。当前生产启动校验仍把旧 `finance-agent.deep-seek` 连接属性当作必填项，既阻止管理员先启动应用再配置模型，也和数据库配置成为唯一运行时连接来源的约束冲突。

## Goals / Non-Goals

**Goals:**

- 将生产启动校验与模型调用期校验分离。
- 生产启动仅校验部署级加密主密钥，而非废弃的模型连接环境变量。
- 无启用连接时保留应用可用性，并使真实模型调用安全失败。

**Non-Goals:**

- 不修改模型连接表、管理 API 或 Stub 行为。
- 不在启动时自动创建、启用或迁移任何模型连接。
- 不改变 P2 的生产部署与外部模型联调边界。

## Decisions

1. 生产启动校验不再读取 `DeepSeek` 的 API Key、Base URL 或模型名称；这些值仅能通过持久化模型连接提供。
   - 原因：旧变量会形成第二个运行时连接来源，且阻止无连接配置时进入管理员页面。
   - 替代方案：保留旧变量作为后备连接。拒绝，因为会绕过管理员配置、审计和密钥加密边界。

2. 生产启动必须校验模型加密主密钥存在且可被 AES-GCM 组件接受；真实模型调用仍在每次调用期检查当前启用连接和可解密的 Key。
   - 原因：主密钥是部署基础设施秘密，缺失时允许应用启动会导致管理员保存 API Key 后才暴露不可恢复错误。
   - 替代方案：启动时要求存在启用模型连接。拒绝，因为首次配置和故障修复无法进入管理页面。

3. 配置错误保持业务可理解且不含密钥、密文、URL 或供应商原始错误。

## Risks / Trade-offs

- [应用可在没有模型连接时启动] → 真实调用在连接解析前明确失败，并由前端提示管理员启用配置。
- [主密钥格式不合法] → 启动阶段失败，避免写入无法解密的密文。
- [遗留部署仍配置旧变量] → 忽略连接变量但保留兼容属性，不主动读取或记录其内容。

## Migration Plan

1. 升级应用前配置 `FINANCE_AGENT_MODEL_SECRET_KEY`。
2. 启动应用并由平台管理员在页面中维护、启用模型连接。
3. 移除部署清单中旧 DeepSeek 连接变量；回滚仅回退应用版本，不改变数据库连接记录。
