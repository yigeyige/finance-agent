## Context

当前业务模型 Bean 在应用启动时按 `finance-agent.deep-seek` 的 YAML/环境变量构造，无法由管理员在线管理；业务场景 Skill 已能维护但与任务和模型上下文没有关联。需要在不暴露 API Key、不接受前端任意模型上下文、且保留 Stub 测试边界的前提下，将两项能力接入现有业务处理向导。

## Goals / Non-Goals

**Goals:**

- 管理员可维护多条 OpenAI 兼容模型连接，并明确唯一启用项。
- 模型调用在每次请求时解析当前启用配置，使启停与切换不依赖应用重启。
- API Key 以 AES-GCM 密文保存，接口仅返回是否已配置；加密主密钥仅作为部署级密钥通过运行环境提供，不是模型连接配置。
- 任务在创建时可关联一个 Skill；后续初稿和会话修订从服务端读取该 Skill 的受控字段并投影给模型。

**Non-Goals:**

- 不实现供应商模型测试、流式输出、模型调用历史或多模型路由。
- 不把 Skill 的文本作为系统指令、工具定义或可执行内容。
- 不迁移已完成任务，也不自动为历史任务猜测 Skill。

## Decisions

### 模型配置与密钥边界

新增 `governance.model_connection_config`，保存配置名称、显示名称、提供方、API URL、模型名称、推理强度、启用状态与审计字段。API Key 仅保存为密文；新增或更新请求提供非空 Key 时才替换密文，读取响应只返回 `apiKeyConfigured`。使用 AES-GCM 的 `ModelApiKeyCipher`，部署级主密钥由 `FINANCE_AGENT_MODEL_SECRET_KEY` 读取；它不包含 API URL、API Key 或模型名，因而不构成模型连接配置。缺少主密钥时可以查询配置，但拒绝新增或替换 API Key，真实调用安全失败。

备选方案是明文保存 API Key 或继续把 Key 放在 YAML 中。前者违反不可读安全边界，后者不能满足管理员维护需求，均不采用。

### 唯一启用模型与按调用解析

表上使用局部唯一索引保证最多一条 `enabled=true` 记录。启用切换在单个事务中先停用旧项再启用目标项；禁用当前项后没有启用模型的调用返回业务可理解错误。`BusinessModelClientFactory` 按当前启用配置构造短生命周期真实 Client，避免单例 Bean 缓存已被编辑的连接信息。Stub Client 保留为明确测试路径，不读取真实连接配置。

### Skill 与任务的稳定关联

为 `task.investigation_task` 增加可空 `business_scene_skill_id` 外键。业务人员可从 Skill 目录进入向导，或在任务创建页选择当前有效 Skill；创建任务时写入关联。模型服务只通过任务关联查找 Skill，并将 `name`、`description`、`handlingType`、`premiseType` 作为 `sceneSkill` JSON 对象放入业务处理初稿与会话修订上下文。未关联 Skill 时保留通用向导行为；关联已删除或无效 Skill 时拒绝调用，避免无提示降级。

不采用标题关键词自动匹配，因为其结果不可追溯且可能把错误场景交给模型。

### 权限和用户界面

模型配置的读写均要求 `PLATFORM_ADMIN` 与现有 `CONFIG_MANAGE` 前端权限。侧栏以“大模型配置”替代含糊的“配置管理”，页面采用现有 Element UI 表格和弹窗，提供新增、编辑、启用、停用；Key 输入框始终为空且以“已配置/未配置”状态展示。业务场景 Skill 目录的“开始处理”带上场景标识，向导在创建任务时提交其关联。

## Risks / Trade-offs

- [部署未提供主密钥] → 管理员不能写入 Key，真实调用被安全拒绝；页面明确提示部署密钥未就绪。
- [数据库中没有启用模型] → 保留任务创建，模型请求返回“请先启用大模型配置”，不制造伪模型结果。
- [启用配置更新期间并发调用] → 调用前读取并快照配置，一次已开始调用继续使用该快照，后续调用使用新配置。
- [Skill 被删除] → 与其关联的任务在请求模型时明确提示场景已不可用，管理员须重新选择或恢复有效 Skill。

## Migration Plan

1. 新增模型连接表、唯一启用索引和任务 Skill 外键的前向迁移。
2. 先发布数据库与服务端，历史任务的关联字段保持空；再发布前端选择与配置页面。
3. 回滚只停止新版本应用，不回写或删除新表/列；旧版本忽略新增可空字段。

## Open Questions

- 当前范围固定为 DeepSeek/OpenAI Chat Completions 兼容协议；新增非兼容供应商时另行增加适配器，不复用本次连接记录。
