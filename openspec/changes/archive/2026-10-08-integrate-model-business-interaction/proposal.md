## Why

当前业务向导把固定规则包装成“系统建议”，但没有真实模型调用，也没有向业务人员说明模型何时参与、使用什么范围的数据以及何时需要人工确认。这会让 Agent 能力与普通流程表单无法区分，也容易造成对自动结论的误解。

## What Changes

- 新增受控业务模型交互 API，在范围确认后生成推荐调查方案，在证据就绪后生成业务摘要、风险判断和后续建议。
- 复用现有 AgentScope DeepSeek 适配器；真实模式调用已配置模型，Stub 模式返回明确标识的确定性模拟结果，不伪装成真实模型。
- 模型只接收当前任务、已确认范围和脱敏证据摘要；输出使用严格 JSON 结构，过滤思考过程并返回可审计的非敏感元数据。
- 调查向导增加“模型分析中—模型建议—人工批准”阶段，决策包增加“模型分析证据—人工核对—生成草稿”阶段。
- 模型不可用或输出非法时安全失败，保留用户当前数据并提供中文重试提示。

## Capabilities

### New Capabilities

- `business-model-interaction`: 定义方案生成、证据分析、Stub/真实模式标识、结构化输出和安全失败边界。

### Modified Capabilities

- `plan-approval-progress-ui`: 调查方案改为后端模型生成，并明确展示模型状态、依据和人工审批边界。
- `packet-draft-assembly-ui`: 决策包组装前增加模型证据分析，模型结论进入业务摘要和建议后再由人工确认。

## Impact

- 后端新增模型交互应用服务、DeepSeek/Stub 实现、配置装配、REST API 和契约测试。
- 前端新增模型交互 service，调整工作台和决策包页面的步骤、状态与错误处理。
- 不新增第三方依赖，不修改数据库结构；复用现有 AgentScope 2.0.3 与 DeepSeek 配置。
