## Context

`backend/src/main/java` 的生产类型已有中文职责说明，但存在两种格式：早期类型使用完整元数据模板，后续部分类型保留为单行 Javadoc。当前盘点发现 441 个类型未满足完整模板。此变更仅统一源码文档格式，不改变运行时行为。

## Goals / Non-Goals

**Goals:**

- 使每个生产顶层 Java 类型的 Javadoc 均包含职责、项目版本、作者和日期。
- 复用已有中文职责描述，避免无意义地重写业务说明。
- 通过可重复的静态检查防止遗漏、类型注解顺序错误或模板字段缺失。

**Non-Goals:**

- 不补充构造器、简单访问器或其他成员级注释。
- 不改变代码逻辑、测试逻辑、API、配置、依赖或数据库结构。
- 不将测试源码纳入本次生产源码注释规范化范围。

## Decisions

- 以 `backend/pom.xml` 的项目版本 `0.1.0` 作为所有类型 Javadoc 的 `@Version`。这与构建产物的真实版本一致，避免在注释中引入独立版本来源。
- 保留旧式 Javadoc 的中文职责文本，并将其嵌入 `@Description` 字段；对确实缺失说明的类型，根据当前类型、包路径和实现补充简短职责。相比按类名机械生成文本，该方式保持业务可读性。
- 仅处理 `backend/src/main/java` 中的非包描述顶层类型。现有主规格的覆盖边界与此一致，测试类不属于生产运行源码。
- 批量变更后执行结构化静态检查、差异空白检查和 Maven 编译/测试。Javadoc 不影响字节码行为，但编译与既有测试可防止意外编辑错误。

## Risks / Trade-offs

- [批量编辑错误匹配成员注释] → 仅识别声明前的类型级 Javadoc，保留成员注释和类型代码不变，并对每个生产文件复检。
- [注释与注解顺序不一致] → 静态检查验证 Javadoc 在类型连续注解之前。
- [大量纯文档差异增加审阅负担] → 仅修改不合规类型，已有完整模板的类型不重写。

## Migration Plan

无需迁移或发布。若需要回退，恢复本变更中仅包含 Javadoc 的源码差异即可，运行时行为不会受影响。
