## Context

当前任务仓储对全部任务和个人任务查询均硬编码 `LIMIT 50`，控制器直接返回数组。平台管理员可查看全部任务并进入只读详情，但详情未返回发起人标识。数据库已保存发起人与创建时间，无需迁移即可进行分页、筛选和审计展示。

## Goals / Non-Goals

**Goals:**

- 以创建时间倒序提供有上限的分页读取，并返回总数。
- 在数据访问层强制普通操作人员的发起人范围，管理员查询不受该限制。
- 提供中文、标准化的表格筛选与分页体验。

**Non-Goals:**

- 不提供任意 SQL、导出、批量操作、全文检索或审计记录编辑。
- 不改变任务详情的业务、范围和方案内容，也不暴露模型密钥或模型原文。

## Decisions

### 由仓储承担身份范围与筛选条件的组合

应用服务根据可信身份选择“全量”或“发起人范围”仓储调用，再将状态与标题关键字传入参数化 MyBatis-Plus 条件。相比先查询再过滤，这避免越权数据进入应用内存，也避免固定列表截断。

### 使用一基页码与每页最大 100 条

REST 接口接受一基 `page`、`pageSize`，默认 20、最大 100；响应携带总数、当前页和实际页大小。这样适合 Element UI 分页组件，并对一次读取设置明确上界。

### 审计信息只补充发起人标识

详情只增加已经持久化的 `initiatorUserId`，不新增人员资料联表或身份目录查询；普通用户只会看到自己的标识，管理员可据此追溯跨任务归属。

## Risks / Trade-offs

- [总数统计带来额外查询] → 限制页大小并使用同一过滤条件；任务历史追溯需要准确总数。
- [标题模糊查询在大数据量下变慢] → 关键字长度受限且仅匹配任务标题；后续索引优化独立处理。
- [接口数组改为分页对象] → 同步 OpenAPI、生成边界和唯一前端调用方，不保留静默兼容分支。

## Migration Plan

无数据迁移。前端与后端同次发布；回滚时恢复旧数组接口和前端列表即可。
