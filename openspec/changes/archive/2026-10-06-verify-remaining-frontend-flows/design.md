## Context

当前 Vue 2 工作台将当前任务保存在 `WorkbenchHome` 组件实例中，离开首页后组件被销毁；路由守卫又在 `App.created` 加载身份之前同步查询权限。因此正常页内跳转、返回和深链刷新的行为不一致。同时项目固定在 Element UI 2.0.0，但部分模板使用了该版本未提供的组件。

## Goals / Non-Goals

**Goals:**

- 让受保护页面的深链刷新等待身份结果后正确放行。
- 保留单次 SPA 会话内的工作台任务状态，并使子页返回目标确定。
- 任务参数变化后重新查询对应数据。
- 使 SSE 显式按最新游标恢复，并给出准确的页面状态。
- 消除因 Element UI 版本基线导致的未知组件和属性类型告警。

**Non-Goals:**

- 不新增任务列表或按 taskId 查询任务基础资料的后端 API。
- 不将合成证据 Worker 暴露为生产工作台按钮。
- 不升级 Element UI 或改变项目整体视觉体系。

## Decisions

1. 在身份服务中增加可共享的单次加载 Promise，路由守卫和根组件共用该结果。这避免双重请求及守卫在缓存尚未建立时误判无权限。
2. 在根组件对 `WorkbenchHome` 使用 `keep-alive`，保留页面内已建立的任务、计划和审批上下文。不将业务数据写入 localStorage，避免长期残留和过期任务状态。
3. 子页使用显式路由返回首页或上一个任务步骤，不依赖不可预测的浏览器历史。
4. 诊断、证据和已发布页监听 `$route.params.taskId`，参数变化后重置短暂状态并重新请求。
5. SSE 客户端关闭旧 `EventSource` 后延时建立携带 `lastEventId` 查询参数的新连接；连接曾成功打开后的断开在页面表达为等待新进度，解析失败仍是错误。
6. 将未被 2.0.0 支持的分隔、空状态和描述组件替换为语义化 HTML 与项目样式，而不通过假的全局组件去模仿新版 API。

## Risks / Trade-offs

- [SPA 内存缓存不跨刷新] → 刷新深链保留当前子页的 taskId 和服务端数据；返回首页时不伪造可编辑任务上下文。
- [SSE 重连可能持续] → 关闭前一连接、使用单个重连定时器，并在组件销毁时清理。
- [手写结构与新版 Element UI 样式不完全一致] → 复用已有颜色、边框、间距变量，并用真实浏览器回归可读性。

## Migration Plan

- 前端静态资源替换后即时生效，无数据迁移。
- 如需回滚，恢复路由守卫、根组件和页面模板即可，后端与数据库不受影响。
