## Context

EMS 数据库连接配置已提供唯一启用连接、加密凭据、固定连通性探针、MySQL 短生命周期只读连接、查询超时、最大行数和 `EmsReadOnlySqlGuard`。该能力当前仅由业务处理模型在生成建议时按需调用，平台管理员没有独立的数据探索界面。

数据探索面向平台管理员，必须与 Agent 的模型规划链路分离：用户提交 SQL 后由服务端立即在已启用连接上执行，不调用大模型，也不保存连接凭据、结果或原始 SQL。现有 Guard 仅允许业务库的单条、库名限定 `SELECT`，不能用于任意 `information_schema` 查询，因此元数据浏览需要固定的服务端读取路径。

## Goals / Non-Goals

**Goals:**

- 在既有工作台中新增平台管理员可见的数据探索入口。
- 让管理员浏览允许业务库的表和字段元数据，并执行符合现有 Guard 的单条 `SELECT`。
- 复用 EMS 连接配置、加密、JDBC 执行器、超时、最大行数和结果投影限制。
- 给出无启用连接、无权限、无结果及安全失败的明确反馈。

**Non-Goals:**

- 不支持任何写入、DDL、导出、查询计划、存储过程、系统库或被排除库。
- 不保存查询历史、收藏、结果集或原始 SQL。
- 不引入第三方 SQL 编辑器、代码高亮或自动补全依赖。
- 不改变 Agent 数据辅助、模型调用或 EMS 业务知识域的既有语义。

## Decisions

### 1. 单独建立数据探索应用服务和 Web API

新增 `dataexploration` 模块，由 Controller 做管理员授权和 DTO 转换，应用服务编排当前启用连接、SQL Guard 和执行器。直接复用 `EmsDatabaseQueryExecutor` 与 `EmsReadOnlySqlGuard`，不由 Controller 直接访问 JDBC。

备选方案是复用业务模型辅助服务。该服务会调用模型规划查询、吞掉运行时失败并将结果定位为模型证据，不适用于需要同步显示错误和结果的人工 SQL 工作台，因此不采用。

### 2. 元数据采用固定服务端查询，并独立于用户 SQL

应用服务通过参数化的固定 MySQL `information_schema` 查询获得允许 schema 中的表和字段名称、注释和类型；schema 和表名都先通过服务端白名单验证。接口不接受用户提供的 SQL 片段、排序字段或任意 schema。

备选方案是让页面执行 `DESCRIBE` 或查询 `information_schema`。现有 Guard 有意拒绝这些语法及非允许业务库，放开它会扩大自由 SQL 表面，因此不采用。

### 3. 查询执行沿用现有硬边界

查询请求仅包含 SQL；服务端忽略页面声称的 schema 和行数，使用当前启用连接的 `maxRows`、查询超时及执行器的 20 列/300 字符单元格投影。前端行数选择只是 `LIMIT` 辅助插入和提示，取值限制为 20、50、100，且不突破连接配置上限。

当没有启用连接时，服务端安全失败；页面引导管理员前往 EMS 数据库配置，不显示任何数据库细节。

### 4. 首版使用单页面本地状态

页面采用 Vue 2 与 Element UI，沿用现有工作台标题、暖白卡片、表格和错误提示模式。使用本地内存维护最多有限数量的查询页签、当前 SQL、结果和结构查看；刷新后丢弃，避免敏感条件与结果被持久化。SQL 输入框使用已有多行输入组件和等宽样式。

备选方案是立即持久化历史/收藏或引入编辑器库。前者需要数据分类、保存期限、权限和审计决策，后者需要新增依赖授权；两者均延后。

### 5. 授权沿用 PLATFORM_ADMIN

首版路由、菜单和后端 API 均要求 `PLATFORM_ADMIN`。现有连接配置也是该角色维护，使用同一边界避免让 `TASK_READ` 用户获得直接数据读取能力。若后续开放给运维角色，应引入独立权限，而不是降低本能力的现有门槛。

## Risks / Trade-offs

- [自由 SELECT 仍可能读取过宽数据] → 保持 Guard、业务库白名单、结果投影、最大行数和平台管理员限制；查询模板化不在首版伪装实现。
- [元数据随 EMS 版本变化] → 元数据按当前启用连接即时读取，页面不缓存为权威知识。
- [查询失败难以诊断] → 服务端仅返回安全失败分类，日志不记录 SQL 或凭据；页面不显示驱动异常原文。
- [无持久化历史降低便利性] → 以当前任务优先保证敏感数据边界，后续单独设计收藏和审计能力。
- [无 SQL 编辑器影响体验] → 首版提供清晰的多行输入、执行快捷键和表/字段插入；后续再基于实际需求评估依赖。

## Migration Plan

1. 发布后，页面默认仅在平台管理员菜单中出现，不影响既有任务或模型分析路径。
2. 管理员先在现有 EMS 数据库配置页面启用并测试连接，再进入数据探索。
3. 回滚时移除新增路由与 API；不会产生业务库写入、迁移数据或持久化查询记录。

## Open Questions

- 首版不开放导出、历史和收藏；如后续需要，需先明确原始 SQL 与结果的敏感等级、保留期限和审计要求。
