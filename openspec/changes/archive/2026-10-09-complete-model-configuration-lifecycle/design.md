## Context

模型连接以 `enabled` 标识当前运行时唯一可用连接。现有启用操作会先停用全部配置再启用目标连接；当没有启用配置时，`requireEnabled` 已经用安全且可理解的错误中止真实模型调用。缺失的是管理员主动将当前连接切换为停用的完整入口。

## Goals / Non-Goals

**Goals:**

- 使管理员能够将任意现有连接安全标记为停用，并留下审计时间和操作人。
- 保证停用后读取不到该连接作为运行时配置，页面展示立即同步。
- 让接口、前端类型与 OpenAPI 同步。

**Non-Goals:**

- 不删除连接、不擦除密钥、不新增模型健康探测或多连接负载均衡。
- 不改变未启用连接时已有的模型调用错误提示。

## Decisions

### 复用单条配置更新实现停用

服务读取目标配置并在同一事务内以 `enabled=false` 与新的审计字段写回。相较新增批量停用仓储方法，这会准确限制目标、保留领域对象完整性，并使停用非启用配置成为可重复执行的幂等状态转换。

### 停用不删除密钥或配置

停用是运行时选择状态，不是配置删除。保留密钥密文与配置可以让管理员在确认后重新启用，且仍遵循 API Key 只写不读的边界。

### 页面需要二次确认

停用会使后续真实模型请求进入安全失败状态，因此页面在发起操作前显示中文确认提示；操作成功后刷新列表而不在浏览器缓存任何密钥。

## Risks / Trade-offs

- [管理员停用唯一连接后业务向导不能调用模型] → 这是显式维护状态，后端继续返回已有的安全提示，页面显示“未启用”。
- [重复点击停用] → 服务写入同一停用状态且不抛出异常，前端也会在刷新后隐藏停用操作。
- [前后端调用方式漂移] → OpenAPI、生成边界和服务层同次更新，并以构建校验。

## Migration Plan

无数据迁移。部署后管理员可直接使用停用入口；如需恢复，只需重新启用已保留的连接配置。
