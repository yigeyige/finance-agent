## Why

当前前端开发服务器可以打开页面，但默认 `/api` 请求没有稳定转发到本地后端，导致任务草稿创建等核心操作在开发环境中直接失败。需要建立可验证的本地联调边界，并以真实页面操作校验任务发起、前提和范围确认主流程。

## What Changes

- 修复前端本地开发环境到后端 API 的连接配置，使默认开发启动方式可以访问 `/api/v1/**`。
- 通过实际页面操作复现并修复任务草稿创建以及同一核心流程中的阻断问题。
- 补充与问题对应的前端配置或服务层验证，覆盖成功、失败和重复提交保护。
- 保持生产构建的 API 基址配置方式不变，不引入新的前端框架或组件体系。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `frontend-api-client`: 明确本地开发服务器必须将默认 `/api` 请求可靠转发到本地后端，同时保留显式 API 基址覆盖能力。
- `task-intake-scope-ui`: 明确任务草稿创建成功后页面进入前提来源步骤，并能继续完成前提保存与范围确认。

## Impact

- 影响 `frontend/vite.config.ts`、前端 API/身份服务及任务发起页面中与问题直接相关的最小代码。
- 可能影响本地后端启动配置或测试，但不改变生产接口路径、数据库业务模型和权限边界。
- 验证包括前端类型检查、生产构建、相关后端测试（如有后端改动）和本地页面联调。
