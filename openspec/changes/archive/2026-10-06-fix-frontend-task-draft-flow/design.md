## Context

前端 Axios 客户端默认使用相对基址 `/api`，后端本地 profile 默认监听 `localhost:8080` 并暴露 `/api/v1/**`。当前 Vite 开发服务器没有代理规则，因此浏览器把写请求发送到 5173 端口，页面可打开但核心 API 流程不可用。任务创建还依赖当前身份先加载完成，因此联调必须同时验证身份初始化、任务写入、前提追加和范围确认。

## Goals / Non-Goals

**Goals:**

- 让标准 `npm run dev` 启动的前端可以通过同源 `/api` 调用本地 8080 后端。
- 通过浏览器真实操作验证身份加载、任务草稿创建、前提保存和范围确认。
- 对发现的同一流程阻断问题做最小修复，并保留明确的中文错误状态和重复提交保护。
- 用类型检查、生产构建和必要的后端测试证明改动没有破坏现有契约。

**Non-Goals:**

- 不改变生产部署网关、生产 API 路径或数据库结构。
- 不重做页面视觉设计，不引入新的组件库或 Vue 3 API。
- 不扩展 P2 生产放行功能，不调用真实模型或真实业务源。

## Decisions

1. 在 Vite `server.proxy` 中将 `/api` 转发到可由 `VITE_DEV_API_TARGET` 覆盖的本地后端，默认值为 `http://127.0.0.1:8080`。保留浏览器请求路径，不做 rewrite，因为后端控制器已经以 `/api` 开头。
2. 生产构建继续由 `VITE_API_BASE_URL` 或部署网关决定，不把开发后端地址写入运行时代码。
3. 先使用本地 profile 和现有 stub 配置启动后端，以真实 HTTP 和浏览器页面作为复现依据；若后端业务实现暴露缺陷，再加载后端规范并做最小修复。
4. 回归覆盖任务草稿、前提、范围确认三个连续写请求，并检查加载态、错误态及 row version 传递。
5. 步骤提议成功后使用响应中的任务状态、范围修订和 row version 更新当前任务视图；审批成功后至少同步返回的 row version，并显示明确的中文成功反馈，避免后续操作继续携带旧版本。

## Risks / Trade-offs

- [本地 8080 端口被占用或后端未就绪] → 启动前检查端口并通过 Actuator 健康接口确认就绪。
- [开发代理掩盖生产网关配置错误] → 代理仅存在于 Vite 开发服务器，生产构建仍使用既有相对路径或显式基址。
- [页面操作写入本地测试数据] → 仅使用 local/test 身份和本地数据库，测试标题明确标识为联调数据，不触达生产环境。
- [现有工作区有无关改动] → 提交时只暂存本任务文件，保留 `.env.example` 和 `qa-output/` 不动。
