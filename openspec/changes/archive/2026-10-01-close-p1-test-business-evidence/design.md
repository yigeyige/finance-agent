## Context

P1 的实现、目录、样本、试点预检和量测基线分别由已归档变更交付。当前任务需要在不重新解释测试结果、不接入真实源、不改变 P2 门禁的前提下，形成单一的静态闭环材料。

## Goals / Non-Goals

**Goals:**

- 将可复核的 P1 静态证据、缺陷结论和回归结果汇总为可导航的材料。
- 将未完成的人工运行时活动、正式签署和真实源条件列为 P2 输入与阻断项。
- 提供角色签署模板，明确模板不是实际签署记录。

**Non-Goals:**

- 不接入真实业务源、真实统一认证或生产配置。
- 不执行 P2 任务，不填充容量、成本、保留或正式例外结论。
- 不将静态回归、模板或范围确认描述为人工运行时验证或正式角色签署。

## Decisions

### 使用证据清单而非重新实现检测逻辑

闭环材料引用已存在的规格、自动化测试和受控资产，并记录复核日期与边界。这样避免引入仅用于生成文档的新运行时代码，也使每个结论可追溯到现有交付物。

### 将结论分为已关闭、待人工验证和 P2 阻断三类

“已关闭”仅针对固定测试范围内已由自动化回归或静态检查覆盖的缺陷；未运行的活动不降级为通过。“P2 阻断”保留为输入清单，不能被 P1 任务完成或签署模板解除。

### 签署使用空白模板

技术、功能和数据源角色的模板保留签署字段、日期和适用范围，但不预填姓名、签名、结论或真实源信息。这样可支持后续人工流程，同时防止伪造批准。

## Risks / Trade-offs

- [静态回归不能证明真实运行时性能或真实源语义] → 证据包明确其范围，并将运行时原始数据和真实源授权列为 P2 阻断。
- [已有 P1 工件分散，链接可能失效] → 证据包使用仓库相对路径并在静态核对中检查路径存在。
- [P1 完成可能被误解为生产放行] → 输入清单与签署模板均明确 P2 必须独立审批和实施。
