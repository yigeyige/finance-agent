## Context

`BusinessModelController` 同时保留生产依赖构造器和包内测试替身构造器。Spring 在未标记的多构造器类型上不能推断注入目标，打包 JAR 启动时因找不到默认构造器而失败。

## Goals / Non-Goals

**Goals:**

- 指定唯一的 Spring 注入构造器。
- 保留测试对替身构造器的访问能力。
- 以最小上下文启动测试和实际健康端点验证回归。

**Non-Goals:**

- 不改动模型交互 API、附件解析、数据库或模型连接配置。
- 不重启现有 `8080` 本地实例。

## Decisions

- 在单参数生产构造器上使用 Spring 的 `@Autowired`，明确 Bean 装配入口；包内双参数构造器仅供测试使用。相比删除测试构造器，该做法不改变已有测试依赖。
- 使用最小 Spring Boot 上下文测试覆盖控制器创建；运行时另以 `8081` 独立实例验证，不影响已有服务。

## Risks / Trade-offs

- [本地环境缺少外部依赖] → 使用当前 local profile 与现有可用默认配置，仅验证健康端点；不触发真实模型调用。
- [占用已有端口] → 使用 `8081`，不停止或修改 `8080` 实例。
