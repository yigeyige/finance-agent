## Context

当前已执行 V1–V14，并在七个业务 schema 中形成 34 张业务表、427 个字段；数据库目录未保存表或列注释。Flyway 历史迁移不可改写，新增注释必须使用更高版本的前向迁移。

## Goals / Non-Goals

**Goals:**

- 为现有业务表和字段提供稳定的中文语义注释。
- 让注释迁移在新库和已升级到 V14 的库上均可执行。
- 使脚本对新增但未登记说明的业务字段失败关闭，避免静默遗漏。

**Non-Goals:**

- 不补充或修改数据记录、约束、索引和历史迁移。
- 不在本任务中直接执行本地或其他环境的写库迁移。
- 不为 Flyway history 或 PostgreSQL 系统表增加注释。

## Decisions

- 新增 `V15__add_schema_comments.sql`，使用 PostgreSQL `COMMENT ON TABLE/COLUMN` 写入元数据，符合 Flyway 前向版本纪律。
- 在 PL/pgSQL 迁移中维护七个 schema 的表说明与字段名说明映射，并遍历实际业务 schema 中的表和列；任一对象没有对应说明即抛错。相同字段名使用统一语义，避免四百余条重复 SQL。
- 使用已有建表迁移解析出的表、列清单进行静态覆盖校验，同时用只读数据库元数据核对当前库范围。

## Risks / Trade-offs

- [后续添加字段未更新说明映射] → 迁移遇到未说明字段直接失败，需要补齐注释再发布。
- [同名列存在差异语义] → 仅对跨表含义稳定的字段复用通用说明；业务专用字段单独映射。
- [注释迁移尚未被环境执行] → 本任务只交付脚本与静态验证，实际执行仍由环境迁移流程负责。
