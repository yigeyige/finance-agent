# Design: EMS 数据库连接配置与业务处理模型分析

## 方案

管理员配置名、JDBC URL、账号、超时和最大返回行数；密码使用现有 AES-GCM 密钥体系加密。配置表通过部分唯一索引保证最多一条启用连接。配置接口仅向 `PLATFORM_ADMIN` 开放，响应永不携带密码或密文。

业务模型不持有 JDBC 凭据，也不直连数据库。后端先要求模型生成一条可选的查询建议，再由统一执行器验证并运行。SQL 守卫仅接受无注释、无分号的 `SELECT`，拒绝写入、DDL、会话控制、文件读写、危险函数、系统库和已排除库；数据库连接还设置只读模式、查询超时及最大行数。查询结果以受限行数和单元格长度投影传给模型，标记为“待核验辅助信息”。

未启用连接、模型决定无需查询、SQL 被守卫拒绝、连接失败或执行失败，都只会省略数据库辅助信息并继续既有业务草稿生成；面向用户的错误不含 URL、账号、密码、原始 SQL 或驱动异常。

## 查询边界

- 仅允许模式：`basedata`、`activiti_ems`、`account`、`budget`、`payment`、`quality`、`smart_audit`、`mobile`。
- 强制单条 `SELECT`；不允许 `WITH`、`SHOW`、`EXPLAIN`、调用过程或多语句。
- 每次模型指导最多执行一条查询，按配置约束返回行数（默认 20，上限 100），并截断长单元格。
- 连接账号仍应在数据库端仅授予上述库的 `SELECT` 权限，作为代码守卫之外的第二道边界。

## 兼容性

MySQL Connector/J 由 Spring Boot 4.0.4 BOM 管理为 9.6.0，连接 MySQL 8。迁移只在应用自身 PostgreSQL 的 `governance` schema 中创建配置表，不修改 EMS 源库。
