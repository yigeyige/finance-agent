## Context

现有 `ConfigSourceAdapter` 已提供只读端口、已批准查询和稳定分页契约；`SyntheticConfigSourceAdapter` 用于 P0 合成场景，生产适配器则始终失败关闭。P1 需要一个独立的测试业务源适配器，以仓库受控的虚构样本验证已冻结的目录、字段矩阵和查询边界，且不得通过网络或凭证访问任何真实源。

## Goals / Non-Goals

**Goals:**

- 在本地/测试范围内提供固定、离线的测试业务对象查询。
- 将模板代码、目录版本、参数、字段投影、稳定排序、分页、水位和来源版本固定在适配器内。
- 为拒绝和故障路径提供稳定的领域错误码及可重复 TCK。

**Non-Goals:**

- 不接入 HTTP、数据库视图、任意 URL、任意 SQL、真实身份或外部凭证。
- 不实现第二来源交叉印证、真实源接入、生产配置或生产部署。
- 不改变现有合成适配器的 P0 场景行为。

## Decisions

1. **独立的测试业务适配器与固定 fixture。** 新增 `TestBusinessSourceAdapter`，只接受固定模板和白名单参数；fixture 仅保存虚构业务标识、角色、组织范围和生效语义。相较复用 P0 合成适配器，它能独立版本化并避免 P1 目录语义与 P0 测试场景耦合。
2. **复用既有 `ConfigSourceAdapter` 与 `ApprovedQuery`。** 不新增网络客户端或通用查询语言，适配器在端口边界检查目录版本、模板、参数和页大小。未登记输入在读取 fixture 前拒绝。
3. **投影白名单优先于响应裁剪。** 每个模板预先声明可读字段；fixture 的任何内部字段均不进入返回记录。相较事后删除字段，白名单能证明禁止字段从未进入结果页。
4. **失败关闭并区分可诊断原因。** 使用既有 `SourceAdapterUnavailableException` 与稳定错误码表达目录漂移和测试源不可用；不返回空成功页、不回退生产占位适配器。

## Risks / Trade-offs

- [固定样本不能代表真实数据质量] → 仅将 TCK 作为测试业务源技术验收，后续 P1-006 增补多类型样本。
- [字段矩阵与代码目录漂移] → TCK 对目录版本、模板、投影和 fixture 版本做一致性校验。
- [测试适配器被错误用于生产] → 仅在 local/test profile 注册，并在 prod 显式失败关闭。

## Migration Plan

1. 添加测试 SourceCatalog、fixture、适配器与 TCK，不修改存量源行为。
2. 在 local/test profile 启用适配器；prod 不注册测试数据源。
3. 若需回滚，移除适配器注册和 fixture；生产占位适配器继续失败关闭，无数据迁移或外部副作用。
