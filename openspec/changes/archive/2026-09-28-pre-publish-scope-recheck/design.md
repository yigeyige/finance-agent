## Context

现有 `PacketDraftStatus` 已定义 `CURRENT` 与 `STALE`，但没有发布前范围复核服务。`CoverageEnumerator` 提供了分页遍历能力，本任务在其上游消费已经枚举出的批准范围快照，不能只依赖来源版本号。

## Goals / Non-Goals

**Goals:**

- 对批准范围和当前全量枚举结果按业务对象键进行集合与属性比较。
- 把所有影响发布可信度的变化转成可审计差异，并给出草稿影响判定。
- 通过结果仓储保留每次重查记录，便于发布前复核和后续查询。

**Non-Goals:**

- 不执行真实来源查询、不改写草稿正文、不直接推进任务状态机。
- 不新增数据库迁移；持久化适配留给后续仓储任务。

## Decisions

- **全范围输入显式化**：服务同时接收批准基线和当前枚举集合，确保新增对象也能被发现。
- **多维差异**：除字段摘要外，单独比较生效分类、来源、规则和模板版本，避免只看 sourceVersion 的漏检。
- **保守发布门禁**：只要存在任何差异即 `STALE_DRAFT`；空差异才返回 `READY_TO_PUBLISH`。
- **可替换结果仓储**：定义 `ScopeRecheckRepository`，默认使用进程内实现，不引入数据库契约。

## Risks / Trade-offs

- [Risk] 对象键不稳定会产生大量新增/删除 → 对象键由调用方提供并要求非空，重查结果保留完整差异。
- [Risk] 当前枚举不完整 → 调用方应先完成覆盖度校验；本服务不会把缺失输入默认为无变化。

## Migration Plan

无需迁移。后续接入发布流程时，在发布事务前调用重查服务并将结果写入仓储。
