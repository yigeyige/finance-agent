## Context

前后端本地开发分别通过 Maven 和 Vite 启动。后端依赖仓库根目录 `.env` 提供数据库等运行变量，而 PowerShell 不会自动将该文件导入子进程。缺失变量时应用虽可监听端口，但数据库访问和身份加载失败。

## Goals / Non-Goals

**Goals:**

- 以一个 Windows PowerShell 入口启动两端，并只向子进程注入 `.env` 内容。
- 对已监听的 8080、5173 端口保持幂等，展示复用状态而不重复创建进程。
- 将标准输出与错误输出写入本地运行日志，控制台不打印环境变量值。

**Non-Goals:**

- 不安装 Node、Maven、数据库或前端依赖。
- 不修改 `.env`、业务配置、数据、后端接口或生产启动方式。
- 不承担进程停止和重启职责。

## Decisions

- 使用 `scripts/start-local.ps1` 作为唯一入口。PowerShell 5.1 与 7 均可直接执行，适配现有 Windows 脚本体系；不引入额外运行时。
- 严格从仓库根目录 `.env` 读取 `KEY=VALUE` 行并导入当前脚本进程，再通过 `Start-Process` 派生 Maven/Vite。子进程继承变量，避免把敏感值拼入命令行或日志。
- 使用 8080 与 5173 的监听状态作为幂等判断，而不是扫描进程名；这样可安全复用用户已启动的服务。
- 将日志保存在忽略的 `.runtime/local-logs/`，以时间戳区分本次启动的前端、后端标准输出和错误输出。

## Risks / Trade-offs

- [`.env` 格式不合法或缺失] → 在启动前失败退出并报告文件或行号，不输出其值。
- [端口被非本项目程序占用] → 脚本复用监听端口，用户需自行确认占用者；脚本不终止未知进程。
- [依赖未安装或命令不可用] → 预先检查 Maven、npm 与前端依赖，给出明确错误，不隐式安装或下载。
- [后台进程启动后立即失败] → 保留分流日志路径，控制台输出定位路径。
