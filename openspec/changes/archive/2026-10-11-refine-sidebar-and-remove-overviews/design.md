## Context

工作台将左侧导航和右侧页面放在同一布局容器中，但侧栏目前没有以视口为基准的高度约束，导致短内容页面的导航背景提前结束。任务列表、业务场景 Skill 和大模型配置各自保留了展示重复名称或数量的概览卡片。

## Goals / Non-Goals

**Goals:**

- 使侧栏在页面内容长度变化时始终覆盖完整浏览器视口，并能承载超长菜单。
- 将三个管理页收敛为标题、操作区和内容卡片的直接层级，保留所有既有业务动作。
- 使项目内前端规范与实际页面风格一致。

**Non-Goals:**

- 不改变导航菜单、路由、权限、后端接口、分页参数或数据模型。
- 不重构业务处理向导或只读详情页面。

## Decisions

- 使用侧栏自身的 `100vh` 高度、粘性定位和纵向溢出滚动，而不是依赖外层内容高度。这样右侧短页面不再截断深色导航，长页面滚动时导航仍稳定可用；不使用固定定位，避免覆盖小屏内容与改变既有布局流。
- 删除三个页面模板中的总览节点，并移除仅为总览服务的计算属性和局部样式；保留操作工具栏中的记录数量、筛选、分页与表格。相比仅用 CSS 隐藏，移除模板可避免无意义 DOM 和过期的可访问性标签。
- 在共享样式和前端规范中删除总览卡片约定，使新增管理入口不会重新引入重复概览。

## Risks / Trade-offs

- [窄屏侧栏菜单高度超出视口] → 侧栏本身启用纵向滚动，移动端继续沿用既有自适应布局。
- [移除概览后缺少记录数量] → 保留表格工具栏或记录标题中的“共 N 项”信息。
- [共享样式误伤业务向导] → 仅删除没有其他引用的管理页概览样式，并用全文检索确认。
