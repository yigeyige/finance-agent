## Context

现有 IAM 已保存用户、角色和密码散列，但没有用户管理用例。密码会话缓存身份八小时，停用或降权不会立即生效。任务列表按发起人过滤，场景列表全局共享，异常快照全局单条。

## Goals / Non-Goals

**Goals:** 管理员管理用户和密码；角色统一；服务端按可信身份限制任务及场景写入；按用户隔离最近异常。

**Non-Goals:** 邀请邮件、自助密码修改、历史异常列表、持久化异常、生产发布。

## Decisions

- 用户管理通过应用服务协调用户、角色绑定和密码凭据，数据库唯一约束守护账号及工号；密码沿用 PBKDF2WithHmacSHA256。删除为 DISABLED。
- `admin` 由固定 auth subject 识别，所有管理写接口拒绝；最后一个有效管理员禁止停用或降权，当前管理员禁止自我降权和停用。
- 增加 Flyway 迁移调整角色 CHECK；本库无旧角色账号，开发测试种子更新为两角色。角色解析只接受两种新角色。
- 会话每次请求从持久化用户和活动角色重新解析，停用及降权立即生效；不改变现有随机 Cookie 生命周期。
- 场景 GET 对两角色开放；POST/PUT/DELETE 和附件写操作由服务端验证创建人或管理员；管理页据身份隐藏无权限按钮。
- 任务各入口依赖可信发起人归属校验；管理员可处理全部任务。列表沿用现有分页筛选。
- 异常快照保留全站最近一条并增加按用户最近快照的有界内存映射；HTTP 异常取可信身份，后台模型调用通过任务标识查询可信发起人。无法归属的后台异常只更新全站快照。
- 页面沿用 Element UI 表格、弹窗及现有暖白工作台样式，不增加英文或小号提示。

## Risks / Trade-offs

- [进程重启清空异常] → 与现有单条内存快照语义一致，页面显示空状态。
- [用户数增长使异常映射增长] → 采用有界容量并清理旧项。
- [数据库角色约束修改] → 迁移前确认无旧角色数据；有旧数据时迁移明确失败，避免静默授权升级。
- [后台线程失去请求身份] → 无可信身份时仅写全站快照，不向普通用户展示。

## Migration Plan

Flyway 新迁移更换角色约束；部署前静态检查与构建，用户自行启动并手工验证。回滚需恢复旧应用与数据库备份；不通过自动降级角色绕过权限。
