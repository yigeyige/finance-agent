## Context

P1 已冻结测试 SourceCatalog、字段权限与两个固定测试来源，但当前 fixture 只覆盖少量人员角色记录，不能作为多类型边界回归的黄金基线。本变更只服务 local/test：样本必须固定、虚构、可审阅，并与真实业务对象、真实认证、生产数据和生产放行隔离。

## Goals / Non-Goals

**Goals:**

- 用版本化、不可变的内存样本表达人员、岗位、角色、流程节点与组织/权限范围。
- 对当前、未来、未知与无匹配情形冻结黄金事实和可断言的预期分类。
- 以任务资产记录样本适用范围与当前会话项目负责人的测试范围确认。

**Non-Goals:**

- 不接入、同步或模拟任何真实业务系统、统一认证、生产凭证或真实员工资料。
- 不扩展现有测试只读源的字段投影，也不把参考样本发布为 API 或生产配置。

## Decisions

### 1. 使用独立、仅 local/test 可用的参考样本目录

新增 `TestBusinessReferenceSampleCatalog`，以不可变 Java record 返回固定样本与查询期望；通过 `@Profile({"local", "test"})` 限制 Bean 生命周期。这样不会更改已冻结的测试只读源字段契约。替代方案是直接扩充 `TestBusinessSourceFixture`；未采用，因为它会把参考验证字段混入只读查询投影并扩大 SourceCatalog 契约。

### 2. 用显式状态表达黄金事实边界

每个样本记录 `CURRENT`、`FUTURE`、`UNKNOWN` 或 `NO_MATCH` 中的一种期望状态；`UNKNOWN` 和 `NO_MATCH` 都不是确认事实。替代方案是以空值或注释表达；未采用，因为无法由单元测试稳定校验，也容易被误解为默认确认。

### 3. 测试范围确认记录替代真实签署

以任务资产记录当前会话项目负责人、确认日期和 local/test 限制，并明确该记录不构成真实源、生产字段、认证或发布授权。这符合当前测试业务范围。替代方案是真实责任人签字；未采用，因为本任务没有真实源、真实数据或生产外部影响。

## Risks / Trade-offs

- [固定样本可能遗漏未来业务组合] → 记录适用范围，后续新增场景必须增加样本和黄金事实而非复用“人员离职”单例。
- [测试目录被生产扫描到] → 用 Spring profile 限制，并在测试验证生产 profile 不装配该 Bean。
- [参考事实被误用为真实结论] → 仅使用虚构标识和 `test` 前缀，且确认记录显式限制其用途。

## Migration Plan

1. 增加独立参考样本目录和单元测试。
2. 增加样本矩阵、黄金事实和测试范围确认记录。
3. 静态验证、编译与单元测试通过后，任务进入待确认状态；不启动本地环境、不执行生产部署。

## Open Questions

- 无。真实业务源的样本和签署将在 P2 的独立入口门禁下另行处理。
