## Context

`WorkbenchHome` 被 `<keep-alive>` 缓存以避免在同一任务流程中丢失填写状态，但左侧“新建业务处理”和任务列表的入口只跳转根路由，无法区分回到已有草稿与主动新建草稿。业务场景 Skill 与大模型配置的弹窗也仅使用 Element UI 默认布局。

## Goals / Non-Goals

**Goals:**

- 为显式的新建操作传递轻量路由信号，并只重置向导的本地状态。
- 复用共享弹窗样式，使两个管理页的表单操作保持同一视觉节奏和窄屏可用性。

**Non-Goals:**

- 不删除已创建的后端任务，不修改模型调用、表单字段、权限或密钥存储。
- 不引入新的组件库或改变现有表格页面层级。

## Decisions

- 在新建入口的根路由上附加一次性草稿标识，向导监听该标识并重置本地状态。相较于移除 `keep-alive`，这能保留非新建导航的流程连续性；相较于刷新整个页面，不会重复加载身份或丢失全局状态。
- 向导使用工厂函数生成默认表单，并集中重置任务、模型草稿、方案、聊天和错误状态，避免遗漏某个旧字段。
- 为两个 Element UI 弹窗使用共享类名和全局工作台弹窗样式，保留页面现有表单控件与保存逻辑。暖白卡片、明确标题分割线、表单间距和底部按钮区延续当前工作台风格，而不引入装饰性视觉元素。

## Risks / Trade-offs

- [写请求尚未结束时重置] → 新建入口在写入、模型生成或聊天处理中保持当前状态，避免旧异步结果写回新草稿。
- [路由历史被重复点击填充] → 已处于工作台时使用路由替换，仅更新新草稿标识。
- [共享样式影响其他弹窗] → 样式限定在专用 `workbench-dialog` 类，其他 Element UI 弹窗保持原样。
