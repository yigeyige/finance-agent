## Context

当前生产源码共 27 个非 `package-info.java` Java 文件，覆盖应用入口、配置、诊断和对象存储模块；多数类型和方法没有可供维护者直接阅读的中文说明。已有 `package-info.java` 提供包级边界，本变更在不触碰业务逻辑的前提下补足类型与成员说明。

## Goals / Non-Goals

**Goals:**

- 让每个生产类型和可执行成员都具备简要、准确的中文 Javadoc。
- 在需要时写明配置语义、边界校验、失败类型和安全处理目的。
- 保持代码格式、签名、异常和控制流不变，并通过既有后端验证。

**Non-Goals:**

- 不改变运行行为、接口、配置、数据库或依赖。
- 不重写或翻译第三方 API 文档。
- 不为显而易见的局部表达式堆叠行内注释。

## Decisions

- 使用项目统一的中文 Javadoc 模板作为类型、构造器和方法的唯一注释载体：类型包含 `@Description`、版本、作者和日期；方法包含 `@description`、实际参数、返回值、异常及作者。模板字段无对应语义时省略，避免虚构异常或返回值。
- 注释以职责与约束为中心：公开接口说明调用方可观察的语义；私有方法说明封装的校验、转换或资源处理目的；配置访问器说明对应配置域，不重复 Java 语法。
- 保留并校对现有包级中文说明，避免改动已经准确的注释，减少无意义差异。
- 仅处理 `backend/src/main/java`。测试名称和断言已表达用例语义，且本次目标是生产代码可维护性；避免将测试样板注释化造成噪音。

## Risks / Trade-offs

- [注释与实现脱节] → 注释只描述当前可验证的职责和约束，不预告尚未实现的能力；通过现有测试防止误改代码。
- [访问器注释重复] → 对配置访问器采用简短、领域化描述，避免逐字复述方法名。
- [横切修改遗漏成员] → 基于源码清单分模块审阅，并在完成后执行声明与 Javadoc 范围检查。
