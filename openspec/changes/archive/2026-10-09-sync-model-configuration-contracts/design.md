## Context

`contracts/` 被定义为 API 的唯一事实来源，但当前 OpenAPI 只覆盖早期任务流。近期业务处理向导、业务场景 Skill、大模型连接配置、任务列表与只读详情均已拥有运行入口，前端则以手写接口重复描述这些请求和响应。现有契约校验只校验 JSON Schema 和示例，适合在不启动应用的前提下扩展。

## Goals / Non-Goals

**Goals:**

- 让本轮已上线的 REST 入口、请求字段和安全响应在 OpenAPI 与 JSON Schema 中可追溯。
- 让前端服务依赖唯一的临时生成类型边界，并保留既有运行时校验方式。
- 为新增可写请求提供无真实密钥或真实用户数据的契约样例。

**Non-Goals:**

- 不引入 OpenAPI 代码生成器，也不改写后端 DTO。
- 不调整接口业务行为、鉴权实现、数据库迁移或模型供应商协议。
- 不在本变更中实现模型连接的停用生命周期；该能力由独立任务处理。

## Decisions

### 使用外部 JSON Schema 承载可复用请求与响应模型

OpenAPI 路径通过 `$ref` 指向 `contracts/json-schema` 中的版本化模型；对象模型默认关闭额外字段。这与现有任务契约一致，并允许本地校验器直接验证样例。相较仅在 OpenAPI 内联模型，它更容易复用和执行离线校验。

### 在临时生成边界集中维护前端 API 类型

`frontend/src/api/generated/index.ts` 增加类型及必要的响应解析器；服务层保留调用 URL、请求元数据和少量页面专属组合逻辑。这样在尚未引入代码生成器时，也不会让每个服务维护另一份接口模型。

### 仅记录当前实现的接口语义

契约写明当前存在的 `enable` 生命周期，不提前声明尚未实现的 `disable`。相较于把计划能力先暴露在契约中，此选择避免客户端依赖不可用路径。

## Risks / Trade-offs

- [临时生成边界仍需人工同步] → 通过 OpenAPI、样例、契约校验与前端类型检查共同约束，并在未来独立引入生成器。
- [接口响应包含嵌套对象] → 为任务详情和模型协作建立明确的闭合 Schema，且样例只使用合成数据。
- [模型 API Key 敏感] → 请求 Schema 仅用于校验写入字段；响应 Schema 和前端类型均不包含明文或密文 API Key。

## Migration Plan

1. 补充契约文件、样例及校验映射。
2. 更新前端临时生成边界与服务导入。
3. 运行离线契约校验、前端类型检查和构建；失败时回退本变更的文件即可，不涉及数据迁移。
