## Context

`ModelInputBudget` 用 UTF-8 字节数作为 Token 数的保守上界，在模型调用前执行。当前 `deepseek-v4.1-flash` 未命中名称分档，使用未知模型的 48,000 字节门禁。用户确认该模型输入上限为 1M、输出上限为 384K。运行中的隆地审批场景调查提示词已手动添加禁查规则，仓库迁移仍缺失。

## Goals / Non-Goals

**Goals:** 对该模型采用 500,000 字节输入门禁；将场景调查禁查规则固化为可重复部署的 Flyway 迁移。

**Non-Goals:** 精确 Token 计数、修改输出 token 配置、自动裁剪或拆分模型输入、查询或改写 EMS 数据。

## Decisions

1. 为 `deepseek-v4.1-flash` 增加明确的 500,000 UTF-8 字节输入阈值。输入上限的“一半”用于本地保守门禁，384K 输出为独立上限，不从输入阈值再次扣除。沿用现有字节计量与中文超限错误，其他已知及未知模型阈值不变。较精确的 tokenizer 需要新增模型依赖和验证，本轮不引入。
2. 使用 V35 Flyway 迁移，以固定 Skill ID 和名称双重限定目标行；仅当调查提示词尚未包含该禁查规则时追加一段中文规则。保留现有提示词及决策包/产物生成提示词；对不存在的目标行不执行插入。迁移脚本应在已应用 V29 的环境中运行。
3. 本轮只做静态检查、编译及针对性测试；本地环境启动和迁移实际执行由用户负责。

## Risks / Trade-offs

- [UTF-8 字节数比真实 Token 数保守] → 500,000 字节门禁仍可能早于模型实际 500K Token 上限触发；保留安全边界，后续基于实际调用反馈调整或引入精确计数。
- [目标场景提示词接近 varchar(2000) 上限] → 迁移前先检查追加后的长度，超限由数据库拒绝迁移并保留原内容；本地已读取到当前提示词长度 1,197 字符。
- [其他环境的 Skill ID 不一致] → 迁移只更新既定场景 ID 和名称，未命中时不误改其他场景。

## Migration Plan

1. 发布代码与 V35 SQL 后，用户按现有 Flyway 流程执行迁移并重启后端。
2. 用户读取目标场景调查提示词，确认禁查规则仅出现一次；重试原流程文件生成操作。
3. Flyway 已执行版本不回滚；如需修订提示词，以后续迁移或现有管理员编辑入口调整。
