## Context

系统现有身份解析支持外部 Principal 和 local/test 请求头，角色权限守卫已经覆盖任务、业务场景 Skill 和模型配置接口。IAM 用户表没有密码凭据字段，前端也没有登录页。内网场景要求简单安全，不引入新的认证框架依赖。

## Goals / Non-Goals

**Goals:**

- 在账号密码模式下，用数据库凭据校验建立可撤销的服务端会话。
- 使用不透明、随机、HttpOnly 的 Cookie，且登录失败不泄露账号是否存在。
- 复用现有用户、角色和权限解析，使 PLATFORM_ADMIN 保持最高权限。
- 以迁移脚本幂等初始化默认管理员和密码散列。

**Non-Goals:**

- 不实现密码找回、修改密码、多因素认证、单点登录或跨实例共享会话。
- 不修改现有业务接口的角色权限矩阵，也不移除后端对外部 Principal 的兼容解析。

## Decisions

- 使用 JDK 的 PBKDF2-HMAC-SHA256、每条凭据独立随机盐和常量时间比较；不新增第三方密码库，也不使用自定义摘要或 MD5。
- 使用内存会话存储和固定 8 小时有效期的随机令牌。部署重启将使会话失效，符合内网简单部署和安全失败原则；多实例共享会话不在本次范围。
- 登录模式由 `finance-agent.identity.mode=PASSWORD` 启用；local 和 prod 默认采用该模式，test 配置保留测试身份适配器以维持既有测试隔离。
- Cookie 限定 `/api`、HttpOnly、SameSite=Lax；HTTPS 请求设置 Secure 属性。退出同时删除服务端会话和浏览器 Cookie。
- 默认管理员账号使用固定 UUID 和 `admin` 认证主体。迁移仅在用户或凭据不存在时插入，绝不在升级时重置已修改密码。

## Risks / Trade-offs

- [单实例内存会话在重启后失效] → 登录页提示重新登录；未来多实例部署再引入共享会话存储。
- [默认初始密码风险] → 脚本只保存散列，不记录明文；管理员首次登录后应通过后续密码管理能力更换，本次不实现密码修改。
- [Cookie 在代理 HTTPS 终止时安全标志判断受限] → 部署网关应透传安全请求语义；本地 HTTP 仍可用 HttpOnly 和 SameSite 保护。
