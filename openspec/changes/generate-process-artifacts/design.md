## Context

源头输入可能是模糊的流程说明或用户附件。现有调查可多轮反馈、查询只读 EMS 证据并按需读取场景样例，但决策包调用只接收原始任务信息与数据库证据，尚未接收当轮调查结论。V29 的四个样例对应 EMS 导出 ZIP：文件名含 `BPMN.xml` 的流程模型正文实际是编辑器 JSON，其他三个 JSON 为可选配置。EMS 现有「导入流程集」入口接受 ZIP，不限制文件数量；遇到模型文件会先创建模型、部署并设置运行版本，再导入所附配置。首次上线的真实导入效果由用户手工验证。

## Goals / Non-Goals

**Goals:** 用户按「调查 → 决策包 → 文件」分别点击触发；一份可修订的调查结论承载流程事实并在生成决策包时固定；本场景按该决策包生成文件，提供单文件及可选配置的 ZIP 下载，保留最新和上一次批次。

**Non-Goals:** 不新增独立事实稿或确认按钮；不自动生成下一步；不做会签、并行网关的转换；不在 Agent 中导入、部署或修改 EMS；不自动分块超限模型输入；不扩展其他场景的流程文件能力。

## Decisions

### 调查结论与决策包

- 现有多轮反馈仍是修订入口。仅对「审批流程生成-隆地」扩充当前调查草稿的场景专用结构化流程结论：节点、流转、分支条件、处理人、金额规则、部门模板适用性及待补项。页面仍称「调查结论」，不另建事实稿。证据继续单独累积和展示。
- V29 调查提示词改为区分用户给出的事实、附件提取、EMS 查询佐证与待补项；场景样例只用作格式参考，不得当作目标流程事实。按需查询实际存在的 EMS 表和值集，避免预设 `sys_value_set` 的结构或数据。
- 用户点击「生成决策包」时，服务端固定当前调查结论及当时的关联证据，并送入决策包分析；包正文保存该快照及原有五个文字字段。证据不足时文字方案列出待补项，不能声称可导入。备选方案仅供阅读；若要采用，先通过调查反馈修订，再生成新包。
- 决策包提示词保持五字段输出契约，但说明依据固定调查结论、已知/未知边界及推荐方案；删除 V29 中「文件生成方式另行确定」表述。文件生成只取指定决策包中的推荐方案、固定调查结论和证据，加场景生成文件提示词，不重新读取可变的调查草稿或用户附件。

### 文件模型与转换

- 模型输出小型流程中间表示，Java 按已核对样例生成精确文件。首版仅支持 `draft`、`approve`、`accountant`、`task-pool`、`import-erp` 五类用户任务，以及顺序流转和排他分支；会签、并行等超范围内容列出遗漏原因，不默默转成其他节点。
- 中间表示覆盖节点、流转、条件、处理人、分档和部门模板；明确各关键字段属于调查事实、模板常量、生成技术标识还是 EMS 导入时分配。模型生成的节点标识、流转引用、条件变量和档位互相校验。未知值可留空，已支持流程逻辑保持不动；若空值使模型不能满足 EMS 最低导入要求，该批次标为「待修复」，仍可下载，但不标为可导入。
- Java 工厂生成流程模型编辑器 JSON（按 EMS 导出惯例命名为 `*BPMN.xml`），包含必需的 Start/End、五类用户任务、ExclusiveGateway、SequenceFlow、resourceId 和布局。节点参数、审批规则、部门审批流只在调查结论表明适用时生成；适用但业务值未知时使用可接受的空值并列待补项。审批规则导入格式为 `ApprovalRulesVo` **数组**，而 V29 当前样例是单个对象，生成器以 EMS 导入契约为准并修正样例/提示词的误导。
- 转换前校验结构和跨文件关系；静态导入契约检查通过的批次标为「可导入候选」，实际 EMS 导入仍由用户验证。模型或转换失败时不写入新批次，保留已有最新和上一次批次。不得把「流程已启用但尚未走通」误写成导入失败；用户已接受自行在 EMS 中补全。

### 文件选择与批次

- 每次生成保存来源决策包 ID、修订号、生成时中间表示、文件内容、待补项和导入状态。成功生成后保留最新及上一次两个批次，删除更早批次。若新决策包生成而文件未重新生成，旧批次标「基于旧决策包」且可下载；不自动重新生成。
- 列表默认突出最新批次，上一次折叠展示。每份文件可单独下载；「下载导入 ZIP」始终包含流程模型，其他已生成配置由用户勾选。待修复批次不得提供宣称可直接导入的 ZIP；可提供单文件供用户自行修复。
- ZIP 导入会自动部署、设置运行版本，这是现有 EMS 行为。下载处明确提示这一效果，Agent 不调用 EMS 导入接口。用户自行决定何时导入、编辑和补全。

### 存储、接口与上下文

- 场景 Skill 新增可空 `process_artifact_prompt`，首版仅为「审批流程生成-隆地」配置。V30 新建批次及文件存储，按任务和批次查询；文件下载校验所属任务。批次最多两份，生成、文件写入和旧批次清理在一个数据库事务内完成。
- 服务接口提供生成、批次及文件列表、单文件下载和按用户选择构建 ZIP 下载；POST 仅在已有决策包和本场景提示词时可用。并发生成同一任务时要防止两个批次同时成为「最新」。
- 每次模型调用检查构造后的输入规模，不超过 1M 且服从实际模型可用上下文；超限返回中文提示缩减材料，不自动分块。生成文件提示词描述中间表示契约及空值/遗漏规则，不把 35KB 样例全文无条件塞入每次调用。
- V30 仅修订本场景调查和决策包提示词及新增生成提示词。现有 `GUIDE_HANDLING` 已能请求至多两个场景附件正文；只有发现它确实阻断本场景的按需读取时，才最小修订通用模板。

## Risks / Trade-offs

- **部分流程导入会自动启用**：现有 ZIP 入口部署并设置运行版本；页面明确告知，由用户手工决定导入时机。静态校验无法证明流程业务可运行。
- **空值可能使导入失败**：以 EMS 导入实现和样例确定最低要求；达不到时标「待修复」，不承诺可导入。首次导入由用户手工验证并反馈转换缺口。
- **样例与入口不完全一致**：V29 审批规则为对象，导入代码要求数组；以入口为准做契约测试，不照搬错误样例。
- **两批保留会清理更早文件**：只在新批次完整写入成功后清理，前端明确仅保留最近两次。

## Migration Plan

V30 添加可空提示词列及批次/文件表，旧任务和旧决策包不回填结构化调查结论；缺少固定调查结论的旧包不能直接生成文件，提示重新调查并生成决策包。迁移前后通过静态校验和编译；本地服务启动、数据库迁移和 EMS 导入由用户执行。若导入产物不合格，停止使用该批次并重新生成，不自动修改 EMS 已导入的流程。

## Open Questions

无待用户选择的方案项。EMS 最低可导入字段集合与部分流程真实导入效果属于实施及用户手工验证项，未验证前不能宣称已可导入。
