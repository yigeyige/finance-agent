## Context

当前 `business_scene_skill` 同时承担可编辑配置和运行时提示来源，任务只保存 Skill 标识，后续模型调用读取“当前有效内容”。这会使任务在多轮调用之间发生提示漂移，也让代码中的通用提示、粗粒度过滤规则有机会覆盖业务场景 Skill。新任务还允许不选择 Skill，与“业务说明 + 业务场景 Skill 发起模型分析”的主流程不一致。

本 change 横跨数据库迁移、Skill 管理、任务创建、模型上下文组装和前端默认选择。它只建立稳定的提示输入基线，不实现证据分块或决策包分析。

## Goals / Non-Goals

**Goals:**

- 新任务强制关联一个有效 Skill 修订，同时提供开箱即用的通用默认项。
- 任务冻结可重放的 Skill 修订、内容摘要与系统提示模板版本。
- 将业务语义集中在 Skill，代码只保留安全、格式、权限和工具边界。
- 为现有数据提供可回填、可回滚的 Flyway 迁移路径。

**Non-Goals:**

- 不在本 change 中设计模型 attempt、证据状态或决策包。
- 不允许 Skill 覆盖系统级只读、安全、权限、输出 schema 和脱敏约束。
- 不把业务 Skill 当作可执行代码或允许其自带连接凭据。

## Decisions

### 1. Skill 采用逻辑身份与不可变修订分离

使用稳定的 Skill 逻辑标识承载名称、默认状态和生命周期；每次编辑写入新的不可变 revision。任务保存 `skill_id`、`skill_revision_id`、`skill_revision_no`、规范化内容摘要和系统提示模板版本。

选择不可变修订而不是复制一份可编辑文本到任务，是为了保留来源审计、避免重复大字段，并允许按 digest 验证重放。替代方案“每次调用读取最新 Skill”会造成历史漂移，不采用。

### 2. 前端默认选择，后端强制校验

业务处理页面加载时选择服务端标记的唯一默认 Skill“通用业务分析”；创建请求必须携带 Skill ID。后端在同一事务中解析当前有效修订并冻结，缺失、删除、无当前修订或并发失效均拒绝创建，不隐式补默认值。

前端默认值用于易用性，后端不隐式补值用于保证 API 调用者明确表达业务场景，避免客户端与服务端默认项不一致。

### 3. 默认通用 Skill 由 Flyway 幂等种子迁移创建

后续实施新增版本化迁移，创建逻辑 Skill 与首个 revision，并以稳定业务键保证重复部署安全。默认项：

- 名称：`通用业务分析`
- 处理方式：`INVESTIGATE`
- 提示内容：

> 你是通用业务分析场景助手。围绕用户业务说明分析，不预设具体系统、表、字段、流程或结论。先识别业务目标、对象、时间范围、组织或人员范围、约束和期望输出；信息不足处明确列为待确认，不得自行补造。将问题拆成可验证假设，优先使用当前任务授权的数据源和只读查询获取事实；仅依据返回的受控字段形成判断，不生成或执行写操作，不猜测表关系，不把“未查到”表述为“不存在”。每轮输出需区分已证实事实、推断、冲突、缺口和下一步，并为事实保留来源或证据引用；发现证据冲突时并列呈现，不覆盖历史证据。提出建议时说明依据、风险、影响范围、前置条件和需要人工确认的事项。若需要专门业务规则、专门字段语义或处理动作，提示用户改选对应业务场景 Skill。生成决策包前，仅总结当前证据能够支持的结论，不把模型建议当成事实或已执行结果。

迁移只在稳定业务键不存在时插入，不覆盖管理员后来创建的新修订。默认切换需要事务内唯一性约束。

### 4. 提示按分层模板组装

最终请求由四层组成：不可被 Skill 覆盖的系统安全边界、版本化输出契约、冻结的 Skill 内容、用户业务说明与当轮授权上下文。代码不得包含具体供应商、系统表字段、业务流程或预设结论；代码级文本只允许稳定的安全约束和结构协议。

浏览器只提交 Skill ID，不提交 Skill 正文、revision 或 digest；这些字段均由服务端解析。

### 5. 删除与默认切换受保护

当前默认逻辑 Skill、被任务引用的 revision 和唯一当前 revision 均不得物理删除。管理员编辑产生新 revision；设置新默认仅影响之后创建的任务。既有任务始终读取被冻结修订，即使逻辑 Skill 后续停用。

## Risks / Trade-offs

- [历史任务没有 Skill 修订] → 迁移为历史任务绑定通用 Skill 首版并记录回填来源；若无法安全回填则保留只读、禁止继续模型调用直至人工选择。
- [Skill 文本可能携带越权指令] → 系统安全层优先，Skill 字段限长并作为业务上下文而非系统指令执行。
- [默认 Skill 被误改造成全局行为变化] → 编辑创建新 revision，已有任务不变；默认切换受唯一约束和审计保护。
- [摘要算法或规范化方式变化导致 digest 不稳定] → 摘要算法与规范化版本一并记录，禁止静默替换。

## Migration Plan

1. 增加 Skill revision、默认标记、任务冻结引用及唯一约束所需结构。
2. Flyway 幂等写入“通用业务分析”逻辑 Skill 与首个 revision。
3. 回填历史任务，生成审计记录；无法回填的任务进入需人工选择状态。
4. 部署后端强校验和版本化读取，再发布前端默认选择。
5. 回滚应用时保留新增修订数据；数据库回滚仅移除未被引用的新结构，不删除历史业务记录。

## Open Questions

无。默认 Skill 文本、强制选择、版本冻结和删除策略已经确认。
