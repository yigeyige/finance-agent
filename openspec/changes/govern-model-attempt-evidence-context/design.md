## Context

业务处理的每轮模型调用会执行数据查询并产生关联证据，但当前调用、查询和草稿成功之间没有独立生命周期。查询已经成功而最终模型调用失败时，证据可能已经保存，却无法区分“已采集”和“已由模型分析”。同时，多轮调用没有把权威历史证据稳定带入后续分析。

原始证据必须保留，但不能直接拼入单次提示：按当前单条证据最多 100 行、20 列、每格约 300 字符估算，一条即可约 60 万字符，50 条可达约 3000 万字符。模型的输出 token 设置也不能作为输入上下文保护。

## Goals / Non-Goals

**Goals:**

- 每轮调用都有可审计、不可变的 attempt，证据状态与模型成功状态分离。
- 全量原始证据追加保存，后续分析通过完整索引、确定性裁剪和分块汇总使用。
- 任何压缩结果都能追溯到权威 evidence ID 与 digest，并显式保留冲突和 unknown。
- 重试是否复用证据由确定性条件判断，不覆盖失败记录。

**Non-Goals:**

- 不在本 change 中生成正式 `businesspacket`。
- 不承诺把每个原始单元格都发送给模型；“全部参与”通过索引、分块和明确的截取完整性实现。
- 不新增写入型业务数据工具。

## Decisions

### 1. attempt 是一次业务模型动作的聚合根

初稿、修订和后续决策包分析均以独立 attempt 标识。状态至少包括 `CREATED`、`COLLECTING`、`MODEL_RUNNING`、`SUCCEEDED`、`FAILED`；终态不可改写。attempt 记录任务、轮次、动作类型、冻结 Skill 修订、模板版本、范围摘要、开始/结束时间、失败阶段和非敏感模型元数据。

选择独立记录而不是只在草稿上加状态，是因为失败调用不一定产生草稿，但仍可能产生合法证据。

### 2. 证据事实与分析资格分离

证据追加写入并关联 attempt。查询成功后先标记 `COLLECTED_UNANALYZED`；只有模型成功返回且结构校验通过，相关证据才成为 `ANALYZED`。失败不删除证据，后续重试可在满足复用条件时引用原 evidence ID。证据不会因同一 schema/table/purpose 出现新记录而被覆盖；时间变化与冲突是分析输入。

### 3. 建立权威 Evidence Manifest

每次分析先生成包含所有候选 evidence ID 的 manifest。每项记录来源类型、查询参数摘要、采集时间、来源版本或水位、行列统计、字段白名单、内容 digest、截取标记、冲突组与资格状态。manifest 本身不新增事实，只声明哪些权威记录存在、哪些片段被纳入以及哪些内容未知。

### 4. 使用配置化预算的两级分析

默认建议预算作为初始配置而非代码常量：单分块输入约 10k token、输出摘要不超过 1.2k token，最多 5 块；最终综合输入约 12k token、输出不超过 4k token；每条证据原始切片最多 20 行、单次所有切片最多 100 行且约 24k 字符。实际实现必须以模型连接上下文能力、固定系统开销和安全余量计算可用预算。

确定性流水线：

1. 生成完整 manifest，所有候选证据都有条目。
2. 按任务轮次、证据时间和稳定 ID 排序；字段白名单后生成可复现切片。
3. 超过预算时分块，每块输出仅含 evidence 引用、事实摘要、冲突、unknown 和 digest。
4. 对全部块摘要做最终综合；若块数仍超限，安全失败并要求缩小范围，不静默丢块。

复用现有 `ContextCompressionValidator` 的引用存在性、digest、一致性和 unknown 完整性校验，扩展而不是另建自由文本摘要通道。

### 5. 重试复用条件必须全部相等

仅当任务范围、冻结 Skill 修订、查询参数摘要、来源版本/水位、证据新鲜度策略均未变化且 evidence digest 可验证时复用。任一条件未知或变化都重新查询，旧 attempt 和证据继续保留。新 attempt 通过 `reused_from_attempt_id` 记录来源。

### 6. 失败必须明确可见

查询失败、上下文超限、压缩校验失败、模型超时和结构化输出失败分别记录失败阶段。API 不返回供应商正文、原始提示或敏感数据；页面保留用户输入并展示可重试的中文错误。

## Risks / Trade-offs

- [全量留存增加存储量] → 保持受控字段、压缩存储和生命周期策略；不可通过删除历史来换取提示预算。
- [分块摘要可能损失细节] → 完整 manifest、确定性切片、digest 和 unknown 让损失显式可审计；关键冲突优先进入综合。
- [来源没有版本或水位] → 将复用判定视为不满足并重新查询。
- [并发调用产生乱序轮次] → 使用数据库生成的单调 attempt 序号或唯一键，不依赖时间戳唯一性。
- [配置预算超过供应商限制] → 启动或调用前校验，按连接能力取更小值并保留安全余量。

## Migration Plan

1. 增加 attempt、evidence 状态、manifest/分块摘要和引用关系表。
2. 把既有证据回填为历史来源；无法证明已分析的记录标记为 `COLLECTED_UNANALYZED`。
3. 先双写 attempt 与旧草稿留痕并验证，再切换读取和重试逻辑。
4. 启用有界上下文后移除旧的任意拼接路径。
5. 回滚时保留新表数据，应用可暂时回到旧读取路径，但不得把待分析证据升级为已分析。
