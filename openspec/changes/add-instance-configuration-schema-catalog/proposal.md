## Why

业务处理模型目前每次都直连 EMS 的 `information_schema` 获取表和字段，再按固定粗筛规则选表；配置表容易被漏掉，也增加重复的结构查询。需要为数据库实例保存管理员主动更新的配置结构目录，让模型日常从本地目录定位 `basedata`、`activiti_ems` 的候选表，同时保留实际配置值的受控只读查询。

## What Changes

- 平台管理员在现有“数据库实例”页面手动同步对应实例的配置结构，保存表名、表注释、字段名、字段注释和上次成功同步时间。只纳入 `basedata`、`activiti_ems` 的非空配置候选表，排除约定的日志、历史、备份、日期后缀、临时/测试/复制、事务与 MQ 流水以及 `act_hi_*`、`act_ru_*`。
- 每个实例的成功同步目录独立保存；同步失败保留旧目录。修改 JDBC 地址或账号不自动清除旧目录，只有管理员主动同步才更新。
- 有目录时，模型分析先按关键词检索本地目录，再保留现有的一次模型选表，选表上限改为 10 张。目录仅用于选表和候选字段定位；选表后的实际配置数据仍连接该 EMS 实例，经现有只读守卫查询，规划仍最多三轮。无目录时沿用当前直连结构目录的流程。
- **BREAKING**：有目录但关键词未命中时，明确提示用户并结束本次模型分析，不继续选表、查询配置值或生成初稿。已同步但目录为空也属于该分支。
- 第一版不引入嵌入生成、pgvector 检索、自动同步或新的配置写操作；不复用现有文档分块表，也不纳入 `claim` 业务数据。

## Capabilities

### New Capabilities

- `ems-instance-schema-catalog`: 数据库实例关联的配置结构目录、管理员手动同步、过滤、快照状态与失败保留。

### Modified Capabilities

- `ems-database-connection-analysis`: 模型选表的数据源分流、关键词检索、10 张选表上限及已同步目录未命中的停止行为。
- `business-handling-guidance`: 已同步目录未命中时的中文反馈与初稿生成终止边界。

## Impact

- 后端：新增 `knowledge` schema 下的实例目录持久化与迁移、只读元数据同步和本地检索；调整 EMS 数据库辅助服务与业务处理模型编排。
- 前端与接口：复用“数据库实例”页面，增加手动同步操作及上次成功同步信息；未命中返回可理解的中文提示。
- 验证：覆盖过滤与空表检查、同步成功/失败、实例隔离、未同步回退、目录命中/未命中及现有三轮只读查询边界；运行时手工验证由用户执行。
