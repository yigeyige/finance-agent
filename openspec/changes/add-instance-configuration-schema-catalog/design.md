## Context

`EmsDatabaseAssistanceService` 目前在每次模型分析时调用 EMS `information_schema` 获取允许的表目录和被选表字段，随后一次选表、最多三轮受控只读查询。`knowledge.document/chunk/embedding_set` 已建表但无数据，且数据模型围绕文档分块与向量。管理员已在“数据库实例”页面维护多实例连接并可测试连通性。本 change 为实例增加轻量结构快照，只服务配置表定位；现有另一项 change 正在编辑模型分析链路，实施时须在当前代码上合并而不是覆盖其改动。

## Goals / Non-Goals

**Goals:**

- 管理员手动从指定实例同步 `basedata`、`activiti_ems` 的表字段结构；按已确认规则过滤，并原子替换该实例的成功快照。
- 有快照时从本地快照做关键词检索，再复用一次模型选表与最多三轮只读配置查询；从未同步时保持现有直连流程。
- 已同步但关键词无候选时立即向用户返回中文原因，不生成初稿；同步失败不损坏旧快照。

**Non-Goals:**

- `claim` 业务数据、自动/定时同步、向量检索、嵌入模型、复用文档分块表、配置写操作、重建现有 SQL 查询规划器。
- 依据空表判断系统长期是否使用某功能；空表只代表这次同步时没有记录，管理员可日后重同步。

## Decisions

### 1. 独立快照，按实例关联

在 `knowledge` schema 增加实例结构快照存储，以 `config_id` 唯一关联现有 `governance.ems_database_connection_config`，保存结构 JSON、成功同步时间和表数。一次成功同步写入一份完整快照；快照行存在即代表“已成功同步”，即使结构数组为空也不得按“从未同步”处理。表和字段仅存名称、类型、注释及库名，不存样本行或凭据。通过本地快照读取服务提供候选表与字段，不改现有文档分块表。单实例结构规模有限，第一版使用 JSONB 快照减少表模型与同步写入复杂度；检索性能不足时再考虑拆表或索引。

管理员修改实例 JDBC 地址、账号等连接属性时不自动清除快照；快照仍可能反映旧连接，由页面显示上次成功同步时间提示管理员。此行为按已确认选择保留。

### 2. 手动、只读、整份替换的同步

在现有实例列表操作中增加“同步表结构”，仅 `PLATFORM_ADMIN` 可调用。服务端复用受控连接配置与 JDBC 连接，在固定库白名单内读取 `information_schema.tables/columns`；从已校验的标识符构造只读 `SELECT 1 FROM <schema>.<table> LIMIT 1` 检查当前是否存在记录，不取业务字段。对每张保留表按原始字段顺序保存字段元数据。过滤在同步时执行，不以 MySQL `table_rows` 估计值判空。

名称过滤覆盖日志/历史、备份/复制、日期样式后缀、临时/测试、事务/MQ 流水、`act_hi_*`、`act_ru_*`。过滤使用边界明确的前后缀规则和可审查的样例测试，不能把含 `audit`、`process` 等业务词的配置表笼统排除。任一元数据读取或存在性检查失败时本次同步失败，旧快照保持；新快照只在全部构建成功后于本地事务中替换。同步接口返回安全错误，不暴露连接串、凭据或底层 SQL。

### 3. 两种分析路径与一次选表

任务未选择实例时保持现有模型指导行为。已选择实例但没有成功快照时，原样走当前 EMS 表目录与字段的直连辅助路径，包括原有选表上限。已有快照时，仅在本地快照中按任务标题、业务说明及当前反馈与表名、表注释、字段名、字段注释做确定性关键词匹配；不把完整场景提示词当检索词，以免泛化内容造成误命中。检索结果按匹配强度排序并限制送给模型的表目录大小。模型仍只执行一次选表，但在快照路径最多选择 10 张；这些表的字段从同一快照读取。查询规划最多三轮，业务值查询继续走当前 SQL Guard、白名单、行数与超时约束。

快照存在但无关键词候选时，不退回 EMS 元数据查询、不交给模型从全目录重选，也不生成业务处理初稿。通过明确的未命中结果让业务处理接口返回中文提示，前端在既有错误/提示位置展示。已同步空快照同样走未命中分支。未命中是显式业务结果，不能被当前“辅助查询失败则静默降级”的异常处理吞掉。关键词命中后，模型选出候选表，随后查询实际配置数据时仍连接该 EMS 实例；若受控 SQL 查询失败，维持现有降级行为。

### 4. 不把结构知识当作业务事实

目录只支持定位候选表字段。模型仍须经受控只读查询取得当前配置值，目录中的表注释不得被当成当前配置已生效的证据。保留已选实例范围、SQL Guard 与证据来源标记。关键词路径只减少分析时对 EMS 结构元数据的重复读取，不承诺减少每个问题所需的业务值查询。

## Risks / Trade-offs

- [管理员长时间不重同步或编辑连接后沿用旧快照] → 页面展示上次同步时间；后续配置查询仍受白名单和 SQL Guard 限制，查询失败按现有安全降级处理。用户已选择不自动失效旧目录。
- [关键词匹配漏掉同义词或无注释表] → 同时检索表与字段名称/注释，保留有界候选；无命中明确提示，不伪造结果。根据实际反馈再决定是否补同义词或向量。
- [同步时逐表判空产生额外 UAT 读取] → 只在管理员手动同步时执行，先按名称过滤，再对候选表执行只返回常量的存在性检查，使用连接超时与单表查询超时。
- [并行模型任务导致目录跨版本读取] → 一次分析固定读取同一份成功快照，表与字段来自同一版本。
- [当前工作区已有模型链路未提交改动] → 实施时先核对最新代码和其他 change 的实际状态，仅在当前代码上增量接入；本提案不改其代码。

## Migration Plan

1. Flyway 新增实例结构快照表；现有实例不回填。迁移后所有旧实例仍走当前直连路径。
2. 上线手动同步接口和页面操作，再接入模型分析的快照分流；管理员按需逐实例同步。
3. 若新路径出现问题，可停止使用或清除该实例快照以恢复原直连路径；不得删除 EMS 源库数据。数据库结构回滚遵循项目迁移规则，不回滚已执行的 Flyway 版本。

## Open Questions

无影响第一版范围的待决事项。候选表数量和关键词评分权重由实施时通过静态样例与针对性测试确定，不改变已确认的 10 张模型选表上限。
